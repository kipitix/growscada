5. sql.Open error is logged but execution continues

File: cmd/combined/main.go:62-65
Source: [review]
What’s wrong: After sql.Open fails, the code prints an error but continues to create the repository and start the API server. sql.Open doesn’t actually test connectivity (it’s lazy), so even a successful call doesn’t guarantee the DB is reachable.
Why it matters: The API server starts and accepts requests, but every database operation will fail at runtime with confusing errors.
Suggested fix: Call sqlDB.Ping() after sql.Open and exit on failure:
if err := sqlDB.Ping(); err != nil {
    fmt.Printf("Database ping failed: %v\n", err)
    return
}

# Devices deliver Tag values through one link contract

A Device (a simulator today, protocol adapters later) delivers Tag values to the server only through `internal/devicelink`: `Resolve` a Tag by its name, unique in the Device's Project (`GET /api/v0/projects/{project}/tags?name=`, ADR 0003, ADR 0006), and `Write` its value and Quality (`PATCH /api/v0/projects/{project}/tags/{id}/value`). Until Device Tokens exist (task 34) the Project is named by the Device's configuration and looked up by name when it starts. The link keeps each Tag's Version itself; on `409 Conflict` it rereads the Tag and retries once, because a Device is the source of truth for the values it reports and must not lose them to a concurrent write. A Tag deleted on the server (`404`) stops being written. Unreachable or failing servers (network errors, `5xx`) are transient: retried at startup, skipped until the next tick at runtime. Devices never create or delete Tags — that belongs to the Engineer's tools (`growctl`). We chose one Go contract over letting each adapter talk REST on its own so that the future Device aggregate, its tokens and any transport change land in one place; the device simulator is its first user and the reference for protocol adapters.

## Amendment 2026-10-04: Device is configuration, the Device Gateway is the process

The word "Device" above meant the delivering process. From now on (task 34, `CONTEXT.md`) a **Device** is configuration inside a Project: its protocol, how its Tags are extracted, and — per Environment — where it stands and how to reach it. That configuration is part of the Draft and the Revision. The process that executes it and talks this link contract is the **Device Gateway**, and the device simulator is the first one. A Gateway acts for a Device with a **Device Token**. With that token it fetches the Device's configuration and may write only that Device's Tags; the Project is implied by the token. A token outlives Deploys and Rollbacks, is dormant (refused, not revoked) while the running Revision has no such Device, and ends only when it is explicitly revoked or rotated. A Tag has at most one supplying Device. The link's retry and conflict rules above are unchanged.

## Amendment 2026-10-26: writes state no Version (ADR 0011)

A Tag's value and Quality are its Tag state, held by the Runtime node, with a single writer — its supplier, or people. A write states no Version and the latest write wins: `PATCH …/value` takes `value` and `quality` only, never answers `409 Conflict`, and answers the `seq` the write took. The link therefore no longer keeps Versions nor rereads and retries; what is said above about `409` and the retry no longer holds. A Tag deleted on the server (`404`) still stops being written.

## Amendment 2026-11-01: one token per Device, devices write only to the Runtime node

A **Device Token** is issued on the Runtime node per Device — not per (Environment, Device) pair. An **Environment** is a named set of one Project's Devices with their connection parameters; it is not chosen by a Deploy, and a Device may stand in several of them. The token and the secrets never reach a Revision or a ProjectFile; only their fingerprints do. A Gateway tells the server which Environment it serves by naming it in the request, so one token serves the same Device wherever it stands.

A Device writes **only** to the Runtime node: the link contract above is unchanged, and there is no draft variant of it. The Runtime node checks that the writing Device is the Tag's supplier, in the application layer, inside the same UPDATE that checks the Project and the TagType. The link's rules above are unchanged.

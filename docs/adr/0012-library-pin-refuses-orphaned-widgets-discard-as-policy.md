# A Library Pin is never switched so as to orphan a Widget; a Library's Discard runs as a policy

A Project uses WidgetTypes only through its Library Pins (ADR 0007): editing or removing a WidgetType in a Library's Draft touches no Scene, and what a Project's Widgets see changes only when a Library Pin is added, switched or removed. A Widget cannot outlive its WidgetType (ADR 0010), so switching or removing a Library Pin is refused while Widgets of the Project would be left without their WidgetType; the PortBindings the switch breaks — a port dropped, a type hint narrowed — are removed afterwards by a policy, as for any binding that stops being valid. The check and the writes of Widgets meet on the Library Pin's row: a write of a Scene that adds a Widget or changes its WidgetType locks the row for share and checks the WidgetType in the pinned release in its transaction, a switch or removal locks it for update and checks the Project's Widgets in its own, so neither slips past the other. In the same way a Library Pin locks its Library's row for share, so a Library is never deleted while a Project pins it.

A Library's Discard brings every WidgetType of its Draft back to the latest Library Release — recreating the removed ones, removing the new ones, restoring the changed ones. That touches many aggregates, so Discard only marks the Library and a policy resets each WidgetType in its own transaction (ADR 0008), clearing the mark last. While the mark stands the Library's Draft is read-only: edits of its WidgetTypes, Release and another Discard are refused, so the policy never overwrites an edit and a Release never captures a half-reset Draft. A write of a WidgetType locks its Library's row for share and checks the mark in its transaction, as a Library Pin does against the Library's deletion.

These row locks hold invariants that span aggregates — Scene and Library Pin, WidgetType and Library, Library Pin and Library —, which is a sign that the real consistency boundary is the Draft. They are transitional: once a Draft is one aggregate with a single writer under its EditLock (task 38), the first two become invariants inside it and their locks go; only the Library's deletion, a Library being outside every Project, stays across aggregates. A Library Release takes its number itself — the latest of its Library plus one, unique per Library, retried on a race — so Release changes no other aggregate.

## Considered Options

- Remove the Widgets a Library Pin switch orphans, after a preview: rejected. Until DraftChanges and undo exist (task 38) it would destroy an Engineer's work irreversibly; the Engineer removes or retypes those Widgets first.
- Let a Widget outlive its WidgetType and render it as a placeholder: rejected. It breaks the invariant every Scene, the Player and the ProjectFile rely on.
- Discard in one transaction over all WidgetTypes of the Library: rejected as an exception to one aggregate per transaction (ADR 0008) for a mechanism that task 38 will replace by a Draft aggregate anyway.
- Discard as a policy with the Draft left editable, resetting only WidgetTypes not changed since the Discard: rejected as harder to reason about than a short read-only spell.

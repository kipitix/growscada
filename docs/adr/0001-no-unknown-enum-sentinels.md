# Domain enums have no "Unknown" sentinel

Domain enum value objects (`TagQuality`, `TagType`, `ScriptLanguage`, `EventType`, and future ones) are structs with an unexported field — not bare `int` types — and do not export an `Unknown` value. Their zero value is invalid (`String()` gives `"invalid"`), parsing any unrecognised string — including `"unknown"` and `""` — returns an error, and aggregate factories/mutators reject the zero value. We chose this over the common Go idiom `Unknown = 0` because the sentinel kept leaking into places where it silently meant something else: it could reach the database (stopped only by a CHECK constraint), and `TagTypeUnknown` doubled as "any type" for `InputPort` type hints. When a concept genuinely needs "any" or "none", it is modelled as its own value object (e.g. `PortTypeHint`), not as a sentinel member of the enum.

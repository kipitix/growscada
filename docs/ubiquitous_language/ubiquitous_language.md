# Единый язык

## Базовые понятия ядра SCADA-системы

### 1. Tag (Тег)

#### Определение

Атомарная единица данных, представляющая одну физическую или логическую переменную процесса. Это точка соединения между реальным миром (оборудованием) и цифровым представлением в системе.

#### Характеристики

| Аспект | Описание |
|--------|---------|
| **Identity** | Уникальное имя (например, `PUMP-101.STATUS`, `TANK-203.LEVEL`) |
| **Type** | *Analog* (непрерывное значение) или *Discrete* (дискретное: вкл/выкл, открыт/закрыт) |
| **Value** | Текущее значение |
| **Timestamp** | Момент получения значения (различаем *source time* и *server time*) |
| **Quality** | Достоверность: *Good* (норма), *Bad* (ошибка связи), *Uncertain* (сомнительное) |
| **Metadata** | Единицы измерения, диапазон (min/max), описание |

#### Ключевые инварианты

- Каждый **Tag** имеет уникальный идентификатор в рамках системы.
- **Quality** не может быть *Good*, если значение не было обновлено в течение настроенного интервала (stale data).
- Для **Analog**-тега значение должно находиться в пределах заданного диапазона (иначе это состояние аварии, но не нарушение целостности тега).

#### Пример использования в диалоге

> *«Создай новый тег для температуры в печи. Тип — аналоговый, единицы — градусы Цельсия. Если качество станет Bad, не показывай его на мнемосхеме.»*

### 2. Alarm (Аларм / Тревога)

#### Определение

Уведомление о том, что значение **Tag** вышло за допустимые пределы или возникло состояние, требующее внимания оператора. Alarm — это не просто событие, а *состояние, требующее реакции*.

#### Жизненный цикл

```
INACTIVE (норма)
    │
    ↓ (условие тревоги выполнено)
ACTIVE (активна, неподтверждена)
    │
    ↓ (оператор нажал "квитировать")
ACKNOWLEDGED (подтверждена, но условие еще есть)
    │
    ↓ (условие тревоги исчезло)
RETURN TO NORMAL (вернулась в норму)
```

#### Типы границ (для Analog Tag)

| Тип | Описание |
|-----|----------|
| **HH** | High-High (аварийный верхний) |
| **H** | High (предупредительный верхний) |
| **L** | Low (предупредительный нижний) |
| **LL** | Low-Low (аварийный нижний) |

#### Ключевые инварианты

- **Alarm** не может быть подтверждена (*acknowledged*) оператором, у которого нет прав на данную группу оборудования.
- Подтверждение (*acknowledgment*) фиксируется с **timestamp** и **identity** оператора — это необратимое действие с точки зрения аудита.
- Если **Tag** имеет *Quality = Bad*, связанные с ним **Alarm** должны перейти в особое состояние *"invalid"* или подавляться.

#### Пример использования в диалоге

> *«По тегу давления в ресивере настроены два аларма: High при 8 бар и High-High при 10 бар. High-High требует обязательного квитирования оператором. Если датчик пропадет (Quality — Bad), алармы должны автоматически подавиться.»*

### 3. Command (Команда)

#### Определение

Целенаправленное действие оператора или автоматической логики по изменению состояния оборудования. Command — это *намерение*, которое система должна проверить, выполнить и зафиксировать.

#### Типы команд

| Тип | Описание | Пример |
|-----|----------|--------|
| **Toggle** | Переключить состояние (вкл/выкл) | Запустить/остановить насос |
| **Set** | Установить значение (уставку) | Установить регулятор на 50% |
| **Pulse** | Послать импульс заданной длительности | Открыть клапан на 2 секунды |
| **SBO** | Select-Before-Operate (двухэтапная команда) | Включить высоковольтный выключатель |

#### Жизненный цикл

```
ISSUED (отправлена оператором)
    │
    ↓ (проверка прав, блокировок, режимов)
VALIDATED (проверена)
    │
    ↓ (отправка на контроллер/устройство)
EXECUTING (выполняется)
    │
    ↓ (получен ответ об исполнении)
COMPLETED (успешно выполнена)
    или
FAILED (отказ выполнения)
```

#### Ключевые инварианты

- **Command** не может быть выполнена, если **Tag**, представляющий состояние исполнительного механизма, имеет *Quality = Bad*.
- **Command** блокируется, если активна **Interlock** (блокировка).
- **Command** не выполняется, если **Control Mode** оборудования установлен в *Local* (управление с места).
- Каждая **Command** сохраняется в **Event Log** с полной информацией: *кто, когда, какую команду, на какое оборудование, результат*.

#### Пример использования в диалоге

> *«Оператор отправил команду на запуск насоса P-101. Система проверила блокировки: уровень в приемном резервуаре ниже минимального — команда отклонена. Оператор получил сообщение: "Отказ: блокировка по уровню". Все это записалось в журнал событий.»*

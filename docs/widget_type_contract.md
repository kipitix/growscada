# Контракт скрипта WidgetType

Документ для авторов WidgetType: как скрипт получает данные и что он должен соблюдать. Термины — по `CONTEXT.md`.

## Точка входа

Скрипт WidgetType объявляет глобальную функцию:

```js
function render(inputs) {
  // обновить DOM по inputs
}
```

HTML-шаблон WidgetType уже в документе, когда скрипт выполняется; `render` ищет в нём свои элементы (`document.querySelector(...)`).

## `inputs`

`inputs` — объект с ключами по именам InputPort WidgetType. Каждый вход — объект, значение лежит в `value`:

```js
function render(inputs) {
  var speed = inputs.speed.value;   // number
  var running = inputs.running.value; // boolean
}
```

Ключ есть у каждого InputPort, поэтому `inputs.<port>` определён всегда.

### Типы значений

Значение приводится по TagType привязанного Tag:

| TagType   | JS-тип    |
|-----------|-----------|
| `Integer` | `number`  |
| `Boolean` | `boolean` |
| `String`  | `string`  |

Для порта с type hint «any» тип тоже задаёт привязанный Tag: порт `any`, привязанный к Integer-тегу, получает число.

### Порт без значения

Если у порта нет PortBinding или привязанный Tag удалён, `value` — значение по умолчанию для type hint порта: `0` для integer, `false` для boolean, `""` для string, `undefined` для «any».

### Расширение

В объект входа со временем будут добавляться новые поля (например, Quality порта). Поля только добавляются: смысл и тип существующих не меняются. Скрипт не должен полагаться на то, что других полей у входа нет.

## Многократный вызов

`render(inputs)` вызывается много раз за жизнь виджета: при каждом изменении значений в Operation, а в превью Library и Project — при каждой правке. Функция должна быть идемпотентной: одинаковые `inputs` дают одинаковую картинку, и вызов с неизменившимися значениями не должен ничего сбрасывать (анимации, прокрутку) без необходимости. Состояние между вызовами можно хранить в DOM или глобальных переменных скрипта.

Первый вызов может прийти не сразу после загрузки документа. До него виджет показывает свой HTML-шаблон как есть.

## Песочница

Виджет работает в `<iframe sandbox="allow-scripts">`:

- сеть недоступна: CSP `connect-src 'none'` запрещает `fetch`, `XMLHttpRequest`, WebSocket и EventSource. Всё нужное виджет получает через `inputs`;
- у документа нет доступа к странице GrowSCADA и её хранилищу;
- виджет неинтерактивен: события мыши до него не доходят.

Quality виджету не передаётся: Operation сам рисует поверх виджета маркер худшей Quality среди его портов (жёлтая рамка — Uncertain, красная рамка с затемнением — Bad).

Исключение, брошенное `render`, перехватывается и на остальные виджеты не влияет.

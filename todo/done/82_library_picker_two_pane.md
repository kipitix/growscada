# Страница выбора библиотек: две панели, инлайн-имя и описание, порядок перетаскиванием

Status: needs-triage
Priority: 2
Blocked by: 81

Дизайн согласован грилингом 2026-11-12; серверная часть — задача 81
(`/api/v0/settings/library-order`, ADR 0024). Заменяет нынешнюю страницу
выбора (`ui/picker`) для Library и Project: список, диалог Name+Description
и кнопки Open/Edit/Delete уходят.

## Раскладка

- Десктоп (порог ~720–760 px): слева список (260–280 px, свой скролл),
  справа детали. Список — только имена, выбранная строка — фон
  `--accent`/текст `--accent-text`. Справа: имя (h2), описание, состояние
  («Unsaved changes» и пр.), кнопки.
- Мобильный: те же две области двумя экранами (список → детали, назад
  «← Libraries»), не две колонки. Возврат из редактора — детали той же
  библиотеки; удалённой/404 — список (задача 76).
- Адаптив: inline-стили перебивают медиазапросы, поэтому layout-свойства
  нескольких узлов — в инжектированный `<style>` по `data-picker-*`
  с `!important` (или классы вместо inline), а не ветвление по
  `app.Window().Size()`.
- Клик = выбор, не открытие. Редактор виджетов — кнопка «Открыть» в
  деталях. `OnDblClick` строки больше не открывает редактор.

## Редактирование

- Двойной клик по имени/описанию (десктоп) или карандаш (мобильный) —
  инлайн-поле. Enter сохраняет имя; описание — `textarea`, Enter = перенос,
  Ctrl/Cmd+Enter сохраняет; blur сохраняет оба; Esc отменяет. На мобильном
  Esc нет — нужна видимая кнопка отмены рядом с полем; поле получает
  `AutoFocus`, кнопки деталей остаются в потоке (не `fixed`).
- Оба поля пишутся одним `PUT /libraries/{id}` с текущей парой и версией.
  Ничего не изменилось → запроса нет. Ошибка (имя занято, 409) → поле
  остаётся в редактировании, текст сохраняется, отказ показывается под
  полем (`role="alert"`, `problemText`); 409-версия перечитывает строку и
  не перезаписывает молча.
- Двойного коммита нет (Enter → перерисовка → blur): флаг «сохраняем» и
  сравнение с исходным значением.
- Действия деталей ждут незавершённую запись (как PATCH стрелок в
  Project): ответ по «своей» библиотеке не применяется к другой
  (задача 61).
- Иконки: инлайновые SVG 16 px, `currentColor`, `aria-hidden`,
  `data-icon`; `title` + `aria-label`. Только однозначные действия
  (плюс, карандаш, корзина, ручка, стрелки) — без текста на десктопе; на
  мобильном иконка + подпись. Save/Cancel и подтверждение удаления —
  текстом. Tap-to-tooltip и long-press-tooltip не делать.

## Создание

- «＋» в шапке списка (десктоп 36 px, мобильный 44×44); пустой список —
  CTA «Создать первую библиотеку» в деталях.
- Без диалога и без формы: «＋» добавляет черновую строку, детали
  переключаются в режим создания с полем имени в фокусе; Enter/blur с
  непустым именем → `POST`; пустое имя → черновик исчезает без запроса;
  отказ сервера — в поле.
- Бейдж состояния остаётся: точка у имени в списке (`title` с текстом) +
  полный бейдж в деталях.

## Порядок

- Десктоп: перетаскивание только за ручку `⋮⋮` (нативный HTML5 DnD, как
  WidgetType → сцена), линия-индикатор между строками, `Alt+↑/↓` для
  клавиатуры.
- Мобильный: go-app v11 **не отдаёт touch/pointer-события** (только mouse,
  drag, key, input) — перетаскивание требует JS-интеропа:
  `app.Window().Call("addEventListener", "pointerdown", js.FuncOf(...))` в
  файле `//go:build js && wasm` плюс заглушка для хоста. Long-press 400 мс
  без смещения > 8 px, «поднятая» строка, `touch-action: none` только на
  захваченной строке, авто-скролл в 60 px от краёв, вибрация через
  `navigator.vibrate`.
- Обе проводки зовут одну чистую функцию `move(ids, from, to)`; она, порог
  и расчёт индекса по Y — обычный Go с тестами. Проводка событий тестами
  на хосте не покрывается: проверяется вручную в браузере и на телефоне.
- Оптимистично применить, затем `PUT` полного слитого массива; ошибка
  сети/409 → откат к прежнему порядку + toast.
- Слияние: сохранённые ID первыми (только живые), затем остальные по
  имени. `picker.load` перестаёт сортировать по имени — иначе ручной
  порядок стирается на каждом событии.

## Тесты и проверки

- `data-picker-*` хуки сохранить; состояние — методами (`startEdit`,
  `commitEdit`, `cancelEdit`, `createDraft`, `move`), как сейчас
  `submitDialog`/`doDelete`, потому что тесты монтируют компонент на хосте.
- Тесты: commit по blur, Esc/отмена, «ничего не изменилось», 409, порядок
  и слияние, создание черновой строкой.
- `make build`, `make test`, `make bruno_test`, ручной проход в PWA на
  десктопе и в мобильной эмуляции (консоль без ошибок).

## Comments

Сделано 2026-11-12. Отклонения от спеки и почему:

- **Перетаскивание начинается с ручки сразу, без long-press 400 мс.** При
  `touch-action: none` на самой ручке скролл списка не перехватывает жест,
  поэтому таймер-различитель не нужен, а ручка заодно не даёт случайно
  потащить строку вместо выбора. Остальное как в спеке: `setPointerCapture`,
  авто-скролл у краёв, подсветка цели, `pointercancel` снимает жест.
- **Cancel при создании не коммитит черновик**: кнопка гасит `mousedown`
  (`preventDefault`), поэтому поле не теряет фокус и blur-сохранение не
  срабатывает; создание по-прежнему на Enter и на blur поля.
- **«Edit» — карандаш у каждого поля** (имя и описание отдельно), а не один
  диалог: двойной клик по тексту на десктопе делает то же; «Open» —
  основное действие и осталось отдельной кнопкой.
- **Кнопки-действия — только иконки, без текста на любой ширине** (по
  замечанию после проверки): у них `title` и `aria-label`, а удаление
  подтверждается; текстом остались только Save/Cancel/Create формы.
- **Жест не покрыт тестами на хосте** (JS-интероп компилируется только в
  WASM): покрыта чистая часть — слияние порядка и перестановка через
  `fakeSource`; сам жест проверен вручную в Chrome синтетическими
  `PointerEvent` (перестановка прошла, порядок сохранился, версия 2).
- `GET/PUT /api/v0/settings/library-order` — задача 81; страница читает
  порядок на каждую загрузку списка и отправляет весь слитый массив.

Доработки по замечаниям после проверки (2026-11-12):

- черновая строка Create — выбранная строка списка (единственная
  подсвеченная), список прокручивается к ней; Cancel возвращает прежний
  выбор (он не сбрасывался, но раньше подсветка оставалась на прежней
  строке);
- кнопки-действия без текста и на мобильном;
- исправлено удаление не той сущности: go-app переиспользует элемент,
  если указатель кода обработчика совпал, поэтому Open/Delete несли id из
  прошлого рендера. Обработчики получили `app.EventScope` с id (и с
  позицией для drag), а клик по строке перечитывает сущность по id.

Ревью 2026-11-12/13: что осталось как есть и почему.

- **Расчёт индекса по Y и порог авто-скролла остаются в JS**
  (`drag_touch_wasm.go`): они читают координаты указателя на каждом
  `pointermove`, и перенос их в Go гонял бы WASM-границу на каждое
  движение. В Go остаётся чистая `reordered()` с тестами.
- **`uiutil.Versions` не используется для версии порядка**: помощник ведёт
  версии агрегатов по ID с забыванием на resync; порядок — одна настройка
  пользователя, которая перечитывается на каждую загрузку списка, и
  синтетический ключ не дал бы корректности.
- **`Conflict: UserSettings` не переименован**: ресурсы API называются
  CamelCase-идентификаторами многословных терминов глоссария
  (`LibraryPin` для «Library Pin», `LibraryRelease` для «Library
  Release»), так что `UserSettings` следует той же конвенции.
- **`DEFAULT 1` у `version` оставлен**: остальные колонки версий тоже имеют
  DEFAULT (`libraries.version DEFAULT 0`), и значение совпадает с первой
  сохранённой версией.
- **Обязательный `library_ids` и третий Bruno-запрос оставлены**: это
  закрывает дефект (тело без поля затирало порядок), найденный на ревью
  задачи 81; возврат вернул бы дефект.
- **`↑/↓` и `Enter` в списке, `Esc` в поле создания оставлены**: это
  клавиатурный доступ к listbox, сверх `Alt+↑/↓` из спеки.

Правка после просмотра (2026-11-13):

- **Строки списка сжимались при Create.** Ручка перестановки рисуется
  только когда строку можно тащить, а с черновой строкой её нет — строка
  без ручки была ниже (37 → 29 px на десктопе, 60 → 48 на телефоне), и
  список «дёргался» при нажатии «＋». Теперь высота строки задана в CSS
  (36 px на десктопе, 48 на телефоне), а колонка ручки сохраняется пустой
  (`data-picker-grip-space`), поэтому строки не меняют ни высоту, ни
  положение имён; не влезающий список прокручивается внутри панели
  (`overflow-y: auto` уже был, проверено на окне 1400×420).
- **Кнопки-действия одного квадрата.** Create, Open и Delete — 36×36 на
  десктопе и 44×44 на телефоне (`data-picker-action`); `uiutil.IconButton`
  теперь обнуляет padding текстовой кнопки, иначе размер задавался бы
  padding'ом, а не CSS.
- **Карандаши имени и описания тише действий**: kind `ghost` в палитре
  `uiutil.Button` (прозрачные рамка и фон, приглушённый цвет), 28×28
  (44×44 на телефоне), `opacity: 0.55` до наведения (`data-picker-edit`).
- **Отмена правки — иконка «×», а не текстовая кнопка**: стоит на месте
  карандаша в том же тихом квадрате (28×28, 44×44 на телефоне), но
  `opacity` 0.8 вместо 0.55 — на телефоне нет наведения, которым она бы
  проявилась, а Esc там тоже нет. Стиль «тихих» кнопок теперь один:
  `data-picker-quiet`.
- **Порядок «съезжал» после перестановки.** `load` перечитывает порядок на
  каждое событие списка, и чтение, обслуженное сервером до того, как `PUT`
  лёг, возвращало прежнее расположение; его ответ применялся уже после
  успешной записи (в callback записи обновлялась только версия), поэтому
  страница показывала старый порядок с новой версией — до перезагрузки.
  Теперь `applyOrder` отбрасывает ответ, пришедший во время записи
  (`savingOrder`), а `move` после записи (и после отказа — ответ мог
  потеряться) перечитывает порядок, что заодно делает устаревшими все
  чтения, начатые до неё. Тест `TestPicker_StaleOrderReadDoesNotUndoTheMove`
  воспроизводит гонку (фейк отдаёт снимок до записи) и падает без правки.
- **Проверен сценарий «добавление → перестановка → удаление» в разных
  вариантах** (создал Zzz, перетащил в начало, создал Aaa, удалил Zzz,
  перетащил Aaa в середину, удалил Aaa): DOM всегда совпадает с
  сохранённым порядком, версия растёт только на перестановках. Созданная
  библиотека встаёт в конец непереставленных (по имени) — так и задумано
  слиянием; удалённая остаётся в сохранённом порядке мёртвым ID (его
  игнорирует слияние) до следующей перестановки.
- **Удаление отделено и подтверждается именем** (по замечанию после
  просмотра): кнопка-корзина стоит ниже линии (`data-picker-danger`), а
  нажатие открывает в панели деталей подтверждение: текст
  `Source.DeleteQuestion`, поле «Type "<имя>" to confirm:», кнопки
  Delete/Cancel. Запрос уходит только при точном совпадении имени
  (обрезанного по краям); иначе — «The name does not match» и ввод
  остаётся. `window.confirm` из страницы ушёл (его нет в тестах хоста),
  выбор другой сущности и Create закрывают подтверждение. Тест
  `TestPicker_DeleteNeedsTheName`: неверное имя ничего не удаляет, верное —
  удаляет.
- **В открытом поле — галочка и крестик** вместо карандаша и текстовой
  Cancel: обе нейтральные серые (kind `""`), 28×28 (44×44 на телефоне),
  `data-picker-edit-ok` / `data-picker-edit-cancel`. Обёртка гасит
  `mousedown`, поэтому клик по ним не коммитит и не закрывает поле раньше
  времени.

# Версионирование json структур

Status: ready-for-agent

Правила — в ADR 0005, термин SchemaVersion — в `CONTEXT.md`. Пока все контракты на MAJOR `0`: совместимость не обещается, конвертеры не пишутся, но механизмы внедряются сейчас.

- Четыре контракта, у каждого своя SchemaVersion `MAJOR.MINOR`, начальная `0.1`:
  - серверный API: REST и поток событий (SSE);
  - формат проекта: ProjectFile = Revision;
  - формат операционной записи: Journal-запись, Checkpoint, PlaybackFile;
  - манифесты growctl.

  Конфиг и control API симулятора не версионируются. Вложенные DTO получают версию своего контракта.
- Завести публичный пакет `contract/` в корне модуля (не `internal/`), по подпакету на контракт и MAJOR (`contract/api/v0`, …). Перенести туда DTO из `internal/server/interface/restapi/restdto` и обновить всех потребителей (`apiclient`, `devicelink`, `growctl`, UI).
- Переименовать `/api/v1` в `/api/v0` на сервере, в `apiclient`, UI, тестах и Bruno-коллекции `growscada_server`. Control API симулятора не трогать.
- Заголовок `GrowSCADA-Schema-Version: MAJOR.MINOR`:
  - сервер ставит его во все ответы REST и в ответ, открывающий SSE-поток;
  - `apiclient` и UI отправляют его во всех запросах.
- Сервер всегда разбирает тело запроса строго: незнакомое поле → 400. Если заголовок запроса указывает MINOR новее серверной, в Problem Details прямо написать «клиент X.Y новее сервера X.Z — обновите сервер». Без заголовка запрос принимается. Перекликается с задачей 18.
- Клиенты (`apiclient`, `devicelink`, UI) читают ответы и события толерантно: незнакомые поля и незнакомые типы событий пропускают.
- Манифесты: `apiVersion: growscada/vMAJOR.MINOR`, запись без MINOR читается как `.0`. Текущие манифесты перевести на `growscada/v0.1` (`tests/manifests/`, примеры, тесты). Разбор остаётся строгим. Если MINOR манифеста новее известной growctl — ошибка «обновите growctl», а не «unknown field».
- Генерация JSON-схем из Go-структур в `schemas/<контракт>/<MAJOR.MINOR>.json` (make-цель), схемы коммитятся. Тесты:
  - сгенерированная схема текущей версии совпадает с закоммиченной — иначе забыли поднять версию;
  - каждая MINOR относительно предыдущей той же MAJOR только добавляет необязательные поля;
  - пока MAJOR = 0, второй тест не применяется.
- Форматы проекта и операционной записи ещё не существуют (задачи 25, 29, 36). Здесь завести только их пакеты с константой версии и поле версии в корне документа, чтобы будущие задачи строились на этом.
- После 1.0, не в этой задаче:
  - окно N/N-1 для API MAJOR;
  - миграция jsonb в БД при смене MAJOR;
  - цепочка конвертеров `vN-1 → vN` для импортируемых ProjectFile и PlaybackFile.
- Обновить `AGENTS.md`: раскладка пакетов и правило «при изменении DTO поднять SchemaVersion».
- Запись в `CHANGELOG.md`.

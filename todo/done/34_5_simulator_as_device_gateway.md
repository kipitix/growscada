## Что сделать

### `devicelink` — без изменений контракта

ADR 0004 цела: `Link` остаётся `Resolve` + `Write`. **Меняется только то, как Link получает доступ:**
- `devicelink.NewRESTLink(client, projectName)` → токен вместо имени проекта: проект определяется токеном (GLOSSARY.md), имя проекта больше не передаётся.
- `RESTLink` шлёт `Authorization: Bearer <token>`; `Resolve` ищет Tag по имени в проекте токена.
- `Resolve`/`Write` — те же пути REST, что и сегодня.

### Конфиг симулятора

- Вместо `project:` — `token:` и `environment:` (имя или ID окружения), плюс прежние `server`, `control`, `autostart`, `defaultInterval`, `tags`.
- Симулятор — **одно** окружение; паттерны — параметры Device (протокол `simulation`), то есть конфиг симулятора описывает Device, а не «проект с тегами».
- Строгий разбор YAML, неизвестные поля — ошибка (как сейчас).

### Получение конфигурации

- Симулятор **получает конфигурацию у сервера** по своему токену: `GET /api/v0/device/config?environment=<id>` — Device, окружение, параметры связи и список её Tag'ов (`id`, `name`, `type`).
- Значит, симулятор **не знает** список Tag'ов заранее: он берёт его из конфигурации, а локальный конфиг задаёт, что и как писать (паттерн на Tag по имени).
- Ошибка «токен неизвестен» (401) и «писать нельзя» (403) — по правилам части 4.

### Коды выхода (`cmd/device_simulator`)

Развести коды, как требует задача 34:

| Ситуация | Код |
|---|---|
| `401`, `403` (неверный/отозванный токен, нет прав) | `ExitNoPerm` (77) |
| прочие `4xx` | `ExitProtocol` (76) |
| ошибка TLS, неверная схема URL | `ExitProtocol` (76) |
| тег не найден, несовместимый паттерн, ошибка конфига | `ExitConfig` (78) |
| файл конфига отсутствует | `ExitNoInput` (66) — как сейчас |

Сегодня **любая** нетранзиентная ошибка резолва даёт `ExitConfig` (78) — это и надо исправить. Транзиентные (сеть, `5xx`) — как сейчас: повтор при старте, пропуск до следующего тика.

### SSE для Gateway

- Симулятор может подписаться на `GET /api/v0/device/events` (SSE по токену), чтобы узнать об изменении конфигурации и об отзыве/ротации токена; при обрыве — переподключение и перечитывание конфигурации.
- Обязательно: **перечитывание конфигурации** при изменении (паттерны/состав Tag'ов обновляются).

## Comments

- 2026-11-03 (реализация): `devicelink.NewRESTLink(client, token)` — токен вместо имени проекта; проект читается из нового `GET /api/v0/device` (контракт 0.9, `DeviceIdentityResponse`: запись называет проект в пути, а назвать его может только токен), `Resolve`/`Write` идут прежними путями. `IsUnauthenticated`/`IsNoPermission` отделяют 401/403 от транзиентных ошибок.
- Конфиг симулятора: `token:` + `environment:` (имя резолвится среди окружений проекта; ID — как есть), `--token`/`DEVSIM_TOKEN` переопределяют токен. Симулятор читает конфигурацию (`GET /device/config`) и берёт состав Tag'ов оттуда; локальный конфиг задаёт паттерны. Tag, которого Device не поставляет, и несовместимый паттерн — `ErrConfig` (78).
- Перечитывание конфигурации: SSE `GET /device/events` с переподключением и перечитыванием при обрыве, плюс таймер (`Options.ConfigReload`, 30 с) как fallback; на изменении состава/типов Tag'ов запись останавливается или возобновляется. В статусе control API — `device_id`/`device_name`/`protocol`/`environment`.
- Коды выхода разведены (`exitCode` в `cmd/device_simulator`): 77 — 401/403 (и отзыв токена посреди работы останавливает Gateway), 76 — прочие 4xx, TLS, схема URL, 78 — конфиг/тег/паттерн, 66 — нет файла. Транзиентные по-прежнему повторяются.
- `apiclient`: `WithDeviceToken`, `DeviceIdentity`, `DeviceConfig`, `ListEnvironments`, `DeviceEvents` (SSE, `ErrStreamClosed`; поток без таймаута клиента). Контракт 0.9, `make schemas`.
- Seed: Device `gateway` + окружение `lab` + fixture-токен для dashboard-симулятора; dashboard-теги поставляет `gateway`, а `sim`/`bench` остаются fixture Bruno (он отзывает их токен и удаляет Tag — общий Device убил бы симулятор посреди прогона и не дал удалить Device). `make run_simulator` теперь работает на seed-данных без `growctl apply`.
- Проверено: `make build`, `make test`, `make bruno_test` (87/87 и 6/6 запросов); вручную — запись с токеном, `GET /device`/`/device/config`, перечитывание по `device_updated` (SSE), коды 77 (отозванный токен), 76 (URL без схемы), 78 (Tag не поставляется Device). UI — вне объёма (задача 66).

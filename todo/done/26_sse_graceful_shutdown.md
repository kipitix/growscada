# Остановка сервера не должна ждать SSE-соединения
Status: ready-for-agent

Обнаружено при проверке задачи 16. Пока открыта хотя бы одна вкладка UI, сервер останавливается по SIGINT/SIGTERM около 15 секунд: `gracedown` ждёт `apiServer.Shutdown` до своего таймаута.

## Причина

- `http.Server.Shutdown` закрывает слушатели и ждёт, пока завершатся активные обработчики, но не отменяет их `Request.Context()`.
- Обработчик `GET /api/v0/events` (`restapi/events.go`, `EventsHandlers.GetEvents`) выходит, только когда отменён контекст запроса или закрыт канал клиента `c.messages`.
- Шаг «Event Hub» в `cmd/combined_server/main.go` (`apiRouter.Close()` → `eventHub.Close`) лишь отписывается от EventBus. Каналы подключённых клиентов остаются открытыми (комментарий у `Close` так и говорит), и SSE-обработчики продолжают висеть до таймаута `Shutdown`.
- Побочный эффект: пока сервер останавливается, слушатель уже закрыт, но SSE-поток остаётся живым. Клиент продолжает считать соединение рабочим, хотя новых данных уже не будет.

## Что сделать

- `eventHub.Close` отписывается от EventBus, помечает hub закрытым и закрывает каналы всех подключённых клиентов, так что `GetEvents` сразу завершается, а клиент получает конец потока. `Close` безопасно вызывать повторно и одновременно с `removeClient`/`broadcast` (флаг `closed` у клиента, всё под мьютексом). Комментарии у `eventHub.Close` и `EventsHandlers.Close` переписать.
- `addClient` сообщает причину отказа (hub закрыт / превышен `MAX_SSE_CLIENTS`). `GetEvents` отвечает 503 Problem Details с разным detail: «server is shutting down» или «too many concurrent event stream connections». Контракт API и Bruno не меняются.
- Хуки «Event Hub» и «API HTTP Server» в `main.go` остаются параллельными (`gracedown` запускает хуки одного слоя одновременно), на их порядок не полагаемся: `apiServer.Shutdown` ждёт SSE-обработчики, пока hub дочищает outbox (подключённые клиенты ещё получают его хвост) и закрывает потоки.
- `client_disconnected` при закрытии hub'ом не трогаем: `GetEvents` публикует его как обычно, но hub уже отписан, и событие никому не доставляется. Паники и записи в закрытый канал нет.
- UI не меняется: `eventlog.Bar` уже обрабатывает штатный конец потока (`error` → плашка → переподключение → `EventResync`).
- Тесты в `restapi/events_test.go`:
  - после `Close` открытый `GetEvents` завершается без отмены контекста запроса;
  - новый `GetEvents` после `Close` сразу получает 503 с причиной «server is shutting down»;
  - `Close` безопасно вызвать повторно и одновременно с `removeClient` (`-race`);
  - симптом: настоящий `http.Server` с открытым SSE-потоком, `Close` и `Shutdown` параллельно — `Shutdown` возвращает `nil` задолго до таймаута, клиент получает EOF.

## Приёмка

- `make run`, открыть UI (вкладка Operation), остановить сервер Ctrl+C: процесс завершается за доли секунды, в логе «API HTTP Server stopped» без таймаута.
- В UI сразу появляется плашка «No connection to the server», а после запуска сервера всё восстанавливается само. Переподключение `eventlog.Bar` из задачи 16 работает и в этом случае.
- `make build` и `make test` проходят.

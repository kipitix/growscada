# Страницы выбора Library и Project вместо выпадающего списка

Status: ready-for-agent
Priority: 1

## Задача

В режимах Library и Project выбор библиотеки/проекта сейчас — выпадающий список
сверху (Project) и колонка слева (Library). Уходим от этого: у каждого режима
появляется отдельная **страница выбора** — список сущностей с созданием,
правкой имени и описания, удалением и переходом к редактированию. Возврат к
списку — компактной строкой в левом верхнем углу рабочей области.

Заодно у Project и Library появляется **описание** (`Description`), которого
сейчас нет ни в домене, ни в API, ни в БД. На странице выбора видно, есть ли у
сущности незакоммиченные изменения.

## Решения (грилинг 2026-11-09)

1. `Description` — у `Project` и `Library`: необязательное, ≤500 символов,
   хранится в агрегате, отдаётся в `ProjectResponse`/`LibraryResponse`,
   правится вместе с именем.
2. «Незакоммиченные изменения» для Project считает сервер: новое поле
   `has_unsaved_changes` в `ProjectResponse` (у `LibraryResponse` оно уже есть)
   — по `Version` Draft и `last_commit_draft_version` последнего Commit.
3. Вкладка режима открывает последнюю открытую сущность, как сейчас; страница
   выбора — отдельный экран, на который ведёт компактная кнопка возврата; если
   сущности ещё нет — сразу страница выбора.
4. Возврат — отдельная слим-строка 24–28px в левом верхнем углу контента
   режима, под глобальными вкладками, одинаковая в обоих режимах:
   `← Список · <имя>`.
5. Список: строки `Открыть / Изменить / Удалить`, сверху `Создать`; «Изменить»
   и «Создать» — один диалог с полями Name и Description. В редакторе сущности
   имя и описание не правятся.
6. Статусы в строке: имя, описание, бейдж «Unsaved changes»; у Library —
   существующее состояние (`published` / `unpublished commit` / `never saved` /
   `legacy`) из `LibraryResponse`. Никаких запросов «по одной сущности».
7. Между «выбором библиотеки» и «выбором проекта» переключают глобальные
   вкладки; перекрёстных ссылок со страниц нет.
8. `Operation` и `History` не трогаем: у них остаётся компактный выпадающий
   список выбора проекта.
9. В Library-редакторе левая колонка исчезает; Save/History/Releases/статус/
   автор/Undo-Redo переезжают в слим-заголовок над редактором (как шапка
   Project).
10. «Создать» сразу открывает редактор новой сущности; «Изменить» и «Удалить»
    оставляют на списке. Удаление — с подтверждением.
11. Ошибки диалога (пустое/занятое имя, длинное описание) показываются внутри
    диалога из Problem Detail; ввод сохраняется; сервер — единственный
    валидатор.
12. Список перечитывается при каждом показе страницы, по общим событиям сервера
    (`project_*`, `library_*`) и `EventResync`; правки Draft из другой вкладки
    могут показать устаревший бейдж до повторного открытия.
13. Описание: `textarea` 2 строки в диалоге; в списке — одна строка с `…` и
    полным текстом в `title`; пустое — приглушённое «No description».
14. Поиска/фильтра в v1 нет; список сортируется по имени на клиенте.
15. Одна задача, без цепочки частей.

## Домен

- `project.Project` и `library.Library` получают `Description`; значение —
  необязательное, обрезается по краям, ≤500 символов. Описание — атрибут
  агрегата, не конфигурация: в `ProjectFile`/Deployment/манифесты не попадает.
- Вместо `Rename` — одна операция `Update(expectedVersion, name, description)`
  (для каждого агрегата), записывающая по одному `project_updated`/
  `library_updated`: одна правка из UI — одна транзакция одного агрегата.
- Затронутые упоминания `Rename` в `AGENTS.md`/`GLOSSARY.md` обновить.

## API (contract/api/v0, MINOR: 0.31 → 0.32, `make schemas`)

- `ProjectResponse`/`LibraryResponse`: `+ description`,
  `ProjectResponse: + has_unsaved_changes`.
- `CreateProjectRequest`/`CreateLibraryRequest`: `+ description`.
- `UpdateProjectRequest`/`UpdateLibraryRequest`: `+ description` как
  `*string` — отсутствие поля сохраняет текущее описание, пустая строка
  очищает (старый клиент, шлющий только имя, описание не стирает).
- `has_unsaved_changes` считается по образцу Library: последний Commit Draft
  (`FindLastCommit`) и `Version` Draft; у проекта без Draft/Commit — `false`.
- Bruno: обновить create/update/list запросы проектов и библиотек и их
  проверки (правило 5 `AGENTS.md`).

## Миграции

- `public`: `projects.description TEXT NOT NULL DEFAULT ''`.
- `engineering`: `libraries.description TEXT NOT NULL DEFAULT ''`.

## UI

- Новый компонент страницы выбора (общая оболочка списка + проводка данных
  Project/Library): строки, статусы, «Создать/Изменить/Удалить/Открыть»,
  диалог Name+Description с ошибкой внутри.
- `root`: у режима появляется состояние «список / редактор»; вкладка открывает
  последнюю сущность (ключи `project:projectID` / `library:libraryID` уже есть),
  без сущности — список; `← Список · <имя>` переключает на список и объявляет
  выбранную сущность EventBus-потоку как сейчас.
- `Project`: убрать `projects.Switcher` из шапки режима; сам `Switcher`
  остаётся только в варианте `Selector` для Operation/History.
- `Library`: убрать колонку библиотек, добавить `SetLibrary(id)` и слим-заголовок
  с перенесёнными действиями.
- Список обновляется на показ, на `project_*`/`library_*`/`EventResync` и после
  create/rename/delete; удаление открытой сущности оставляет вкладку на списке.

## Приёмка

1. `GET /projects` отдаёт `description` и `has_unsaved_changes`; `PATCH`
   меняет имя и описание (отсутствие `description` его не стирает); то же для
   `/libraries`.
2. В Project нет выпадающего списка; в Library нет колонки библиотек.
3. Вкладка открывает последнюю сущность; `← Список · <имя>` возвращает к списку.
4. Список: создание открывает редактор; правка и удаление (с подтверждением)
   остаются на списке; ошибки — в диалоге, ввод не теряется.
5. У проекта с правками после последнего Commit виден «Unsaved changes»; после
   Save/Discard бейдж исчезает. У Library — плюс состояние релиза.
6. `make build`, `make test`, UI-прогон в браузере и `make bruno_test` зелёные.

## Вне объёма

- Поиск/фильтр и пагинация страницы выбора.
- Страницы выбора для Operation/History.
- Описание в `ProjectFile`, growctl-манифестах, Deployments и экспортах.
- Массовые операции и drag-and-drop в списке.

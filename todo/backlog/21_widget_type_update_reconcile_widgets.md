# Согласование Widget с изменённым WidgetType — политика по событию
Status: needs-triage
Blocked by: 20

Появилось в архитектурном ревью 2026-10-05; переписано после grilling задачи 20 (2026-10-06, ADR 0008): одна транзакция — один агрегат, межагрегатное — идемпотентные политики по событиям. «Всё или ничего» больше не цель.

## Что не так сейчас

- `UpdateWidgetType` (`application/widget_type_application_service.go`) после `Save(type)` синхронно согласует каждую Scene (`FindByWidgetTypeID` → `ReconcileWith(wt)` → `Save`, до 3 попыток при `ErrSceneConflict`, удалённая Scene пропускается, задача 19).
- Ошибка посреди цикла (не конфликт, например отказ БД): клиент получает 500, WidgetType уже сохранён, часть Scene согласована, остальные сохраняют привязки к исчезнувшим портам навсегда — повтора нет.
- После задачи 20 события согласованных Scene уже попадают в outbox (их записывает `ReconcileWith`), но надёжность согласования по-прежнему зависит от того, дожил ли запрос до конца цикла.

## Что сделать

- `UpdateWidgetType` сохраняет только WidgetType; его `widget_type_updated` лежит в outbox.
- Политика «согласовать Widgets с WidgetType» регистрируется в диспетчере задачи 20: по `widget_type_updated` находит Scene с Widgets этого типа и согласует каждую в своей транзакции (`retryOnRace` на Scene; удалённая Scene пропускается). Исчерпаны повторы или иная ошибка — политика возвращает ошибку, событие повторяется диспетчером целиком.
- Политика идемпотентна: уже согласованная Scene не меняется и не порождает событий.
- Убрать `maxReconcileAttempts` и синхронный цикл из сервиса.
- UI Project: между commit WidgetType и доставкой `scene_updated` есть короткое окно; правка Widget в этом окне получает 409. Проверить, что UI переживает 409 (перечитывает Scene или внятно сообщает), и при необходимости доработать.

## Приёмка

- Тест: при ошибке сохранения одной Scene событие остаётся в outbox; после повторной доставки согласованы все Scene, уже согласованные не изменились.
- Тест: после удаления InputPort и `DrainOnce` в доставленных событиях есть каждая затронутая Scene.
- В браузере: удалить InputPort в Library, затем передвинуть Widget этой Scene в Project — после прихода события 409 нет; если правка попала в окно, UI не ломается.
- `make build` и `make test` проходят.

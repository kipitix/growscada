# Устаревшие ответы в живой перезагрузке UI
Status: ready-for-agent
Priority: 3

Найдено в ревью задачи 29. Все ошибки старые: рефакторинг задачи 29 перенёс их без изменений. Общая причина — ответ, запрошенный до записи, применяется после неё. После 72_6/72_7 к этому добавляются гонки списка saved states, запрошенного до Save/Deploy, и чипов лейблов (85_3).

- Список, запрошенный до создания, считает новый объект удалённым. Для Tag это закрыто (`tagLists`/`tagCreated`, `project/load.go`), для остальных нет:
  - `library/load.go` `setWidgetTypes`: только что созданный WidgetType пропадает из списка, выбор и LocalStorage сбрасываются (`clearSelection`).
  - `project/load.go` `setWidgets`: при быстром добавлении двух виджетов со второго снимается выбор (`pruneSelection`).
  - `project/load.go` `setScenes`: только что созданная Scene пропадает, выбор переходит на `scenes[0]`. `draftVersions.Advance` защищает от отката версии, но список всё равно строится из ответа, в котором нового ID нет.
  - Кандидат на общее решение — `uiutil.Versions`: ID, учтённый через `Observe` после `Mark` списка, не считается удалённым из-за того, что его нет в этом списке. Заменил бы `tagLists`/`tagCreated`. Сейчас `Versions` умеет только не откатывать версию (`Advance`), но не знает, когда ID появился.
- Library не защищена от списка, запрошенного до переименования (у Scene это делает `draftVersions.Advance`): слияние откатывает имя в списке и в редакторе, следующий Apply молча отправляет старое имя.
- Смена выбранной Scene (удалили выбранную, `selectScene`, сцен не осталось): `p.widgets` очищается в `setScenes` (сценарии «выбранной нет» и «сцен не осталось» покрыты), но `selectScene` до ответа старый список не очищает — проверить и закрыть остаток.
- `project/scene_versions.go` `loadStaleScenes`: `staleScenes` очищается до GET. После сетевой ошибки повтора нет, следующая правка этой Scene получает ложный 409.
- `project/edit_fields.go` `widgetEditFieldsOf` округляет геометрию (`%.1f`, `%.3f`), а `saveWidgetGeometry` разбирает текст редактора. Сохранение из панели округляет и поля, которых пользователь не трогал (поворот 37.2846 → 37.3).
- `project/widget_ops.go` `finalizeAllDrags`: **закрыто** — отложенный `loadWidgets` ждёт отправленный PATCH (`waitMoves`), а не идёт с ним одновременно.

## Решения

- Список, запрошенный до создания: общий механизм в `uiutil.Versions`. Если ID учтён через `Observe` после `Mark` списка, отсутствие ID в этом списке не значит, что объект удалён. Применить к WidgetType, Widget, Scene и Tag; `tagLists`/`tagCreated` удалить.
- Library: `setWidgetTypes` через `l.draftVersions.Advance`, как `setScenes`: элемент списка берётся, только если его версия новее известной, иначе остаётся локальный. Второй `Versions` не нужен: у WidgetType версия записи совпадает с версией состояния Draft'а.
- Перетаскивание: сделано иначе, чем предполагалось («если PATCH отправлен, `loadWidgets` не запускается»): загрузка откладывается до завершения PATCH через `waitMoves`, после чего список перечитывает `widget_updated` или `rejectedSceneEdit`.
- Смена выбранной Scene: `p.widgets` очищается в одном месте вместе со снятием выбора виджета и до ответа `loadWidgets` на холсте показывается индикатор загрузки.
- `loadStaleScenes`: при ошибке GET (кроме 404) ID возвращается в `staleScenes` и перечитывается при следующей загрузке. Таймеров повтора нет.
- Округление: в `saveWidgetGeometry` поле, чей текст равен `widgetEditFieldsOf(текущий виджет)`, отправляется точным значением из виджета, иначе разобранным текстом. Отображение не меняется.
- Saved state: список saved states, запрошенный до Save/Deploy, не должен откатывать только что созданную строку или пометку «Running»; общий `uiutil.Versions`/`Mark` и перечитывание по событиям. С задачей 85_3 то же для чипов лейблов в History.

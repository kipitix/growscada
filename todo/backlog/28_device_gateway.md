# Device, Device Gateway, Device Token
Status: ready-for-human
Blocked by: 26

Слой B. Термины — `CONTEXT.md` (Device, Device Gateway, Device Token); обновить ADR 0004.

- Device — сущность проекта, конфигурация (часть Draft и Revision): адрес оборудования, протокол, параметры подключения и как каждый Tag извлекается из протокола. Описательная метаинформация (комментарий), например пометка, что это имитатор; на Quality она не влияет: имитатор поставляет обычные `Good`/`Bad`/`Uncertain`, чтобы имитировать разное качество сигнала (см. задачу 13).
- У Tag не больше одного поставщика значения: один Device (позже — одна Computation, задача 50) или никто (задаётся людьми). Два Device, пишущих один Tag, — ошибка валидации Draft (и отказ Deploy).
- Device Gateway — внешний процесс, исполняющий конфигурации Device и поставляющий значения через devicelink. `devicesim` становится первым Device Gateway: Device с протоколом simulation, паттерны — параметры Device.
- Device Token выпускается на Runtime node на идентичность Device, не входит в Draft/Revision. Gateway с токеном получает конфигурацию своего Device и пишет только его теги; проект определяется токеном.
- Токен переживает Deploy и Rollback. Если Device нет в текущей Revision — токен «спит»: запросы отклоняются (Gateway ждёт), но не отзывается. Отзыв и ротация — только явно; в UI видны «осиротевшие» токены.
- Смена конфигурации Device после Deploy: Gateway узнаёт по SSE и перечитывает. До задачи 29 конфигурация отдаётся из Draft (текущих таблиц), после — из текущей Revision.
- С появлением авторизации — развести коды выхода симулятора (`cmd/device_simulator`): сейчас любая не-transient ошибка резолва тега (в т.ч. `400`/`401`/`403`, ошибка TLS или схемы URL) завершает процесс с `ExitConfig` (78), как «тег не найден». Нужно: `401`/`403` → `ExitNoPerm` (77), прочие `4xx` → `ExitProtocol` (76), тег не найден / несовместимый паттерн — по-прежнему `ExitConfig`. (Из ревью задачи 15.)
- REST, Bruno (обе коллекции), growctl (манифест Device), тесты, `CHANGELOG.md`.

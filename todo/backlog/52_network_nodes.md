Status: ready-for-human
Priority: 3
Blocked by: 50

- Запуск бинарника с ролями Engineering, Runtime или обеими (конфигурация).
- HTTP-реализация интерфейса Engineering→Runtime: Deploy сохранённого состояния, текущая Deployment (с номером `commit_number`), runtime-сущности, токены устройств.
- Отдельные БД по строкам подключения.
- Аутентификация между узлами — после задач 49/50.
- Сервер с одной ролью: в его БД серверная схема `public` и схема этой роли (ADR 0011).
- Очистка удалённого Project без FK между схемами. Сейчас `runtime.tags.project_id` держит FK `fk_runtime_tags_project_id` на `public.projects`; `ProjectRepository.Delete` распознаёт нарушение как `ErrProjectNotEmpty`. С отдельными БД FK нет: строка Project удалится, состояния останутся навсегда. Гарантию даёт сам Runtime: `RemoveProjectTagStates` в одной транзакции удаляет состояния и записывает надгробие Project (`runtime.removed_projects`), `UpsertTagDefinitions` не вставляет определения Project с надгробием (решить: ошибка или пропуск) — проверка и вставка одним запросом. Затем убрать FK `fk_runtime_tags_project_id`, его распознавание в `project_repository_postgres.go` и комментарии про «поздний upsert удерживает строку»; обещание — в доке порта `RuntimeNode`.
- Сверить с этим пунктом хвост очистки из задачи 70: забывание кэша токенов на ветке «строки уже нет».

# Строгие доменные перечисления: убрать Simulated и заглушки Unknown

## Убрать качество `Simulated`

- Качество описывает надёжность значения, а не его происхождение. Если бы имитатор ставил `Simulated`, он не смог бы имитировать разное качество сигнала. Имитатор (задача 15) поставляет обычные `Good`/`Bad`/`Uncertain`, а пометка «это имитатор» — описательная метаинформация `Device` (задача 22).
- Новая goose-миграция: существующие теги с `simulated` переводятся в `good`, `chk_tags_quality` пересоздаётся без `simulated`. `Down` возвращает старое ограничение и данные не трогает.
- API на `"quality": "simulated"` отвечает 400 (Problem Details); breaking change записать в `CHANGELOG.md`.
- Тестовые данные: тег `is_cached` получает `uncertain`. Тест репозитория вместо `Simulated` ставит `Bad` (качество, отличное от исходного).

## Убрать заглушки `Unknown` (см. ADR 0001)

Касается `TagQuality`, `TagType`, `ScriptLanguage`, `EventType`.

- Экспортируемых констант `...Unknown` больше нет. Нулевое значение невалидно, его `String()` возвращает `"invalid"`.
- Разбор строк (`NewTagQuality`, `NewTagType`, `NewScriptLanguage`) на `"unknown"`, `""` и любое нестандартное значение возвращает ошибку.
- Фабрики и мутаторы агрегатов (`NewTag`, `SetValue`, создание/изменение `WidgetType`) отклоняют нулевые значения, поэтому до БД невалидное значение не доходит.
- Начальное качество тега по-прежнему задаёт тот, кто создаёт тег (обязательное поле `quality` в `POST /tags`). К этому вернёмся в задаче 22 (Device).

## `EventType`

- Переделать из `type EventType int` + `iota` в struct VO (`EventType{eventType int}` с var-константами), как остальные перечисления, чтобы снаружи пакета нельзя было привести произвольное число.
- `EventTypeUnknown` убрать; `AllEventTypes()` перечисляет все значения без оговорок.
- `NewEventType` оставить (понадобится для записи/воспроизведения событий, задача 23): на неизвестную строку — нулевое значение и ошибка.
- `EventBus.Subscribe` с нулевым типом не валидируется: такая подписка просто никогда не сработает. Сигнатура не меняется.
- UI-лог событий по-прежнему терпим к незнакомым строкам (категория «Other») — на случай, если клиент старее сервера.

## `PortTypeHint` вместо `TagTypeUnknown` у `InputPort`

- Новый value object в пакете `widget`: либо «любой тип», либо конкретный `TagType` (`AnyTagType()`, `OnlyTagType(t)`, `Accepts(t)`, `TagType() (tag.TagType, bool)`).
- На стыке (REST, JSON-колонка `input_ports`) «любой» — это `""` или отсутствующее поле; `"unknown"` даёт ошибку (400). Миграция данных не нужна: «любой» уже хранится как `""`.
- UI (`uidto.TypeHintLabel`) больше не обрабатывает `"unknown"`.

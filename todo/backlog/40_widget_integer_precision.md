# Integer-значения больше 2^53 теряют точность в виджете
Status: needs-triage

Появилось в ревью задачи 16. Домен хранит Integer-тег как `int64` (`domain/tag/tag_value_integer.go`), а скрипт WidgetType получает его как JS `number`. `number` точно представляет целые только до 2^53 − 1 (`Number.MAX_SAFE_INTEGER` = 9 007 199 254 740 991). Всё, что больше по модулю, молча округляется.

## Где теряется

- REST API и событие `tag_updated` передают значение строкой (`"value": "9007199254740993"`), там точность не теряется.
- `uiutil.NewInput` (`interface/ui/uiutil/srcdoc.go`) разбирает строку в `int64`, `uiutil.InputsJSON` кодирует её JSON-числом, а в iframe `JSON.parse` превращает число в `number`, и значение округляется.
- Так происходит везде, где виджет получает `inputs`: в Operation (`livescene.View` → `postMessage`) и в превью Library и Project (`BuildSrcdoc`).

## Пример

Integer-тег счётчика со значением `9007199254740993` виджет показывает как `9007199254740992`. Нет ни ошибки, ни маркера Quality, Operator видит правдоподобное, но неверное число.

## Что решить

Исправление меняет то, что скрипт получает в `inputs.<port>.value`, то есть контракт `docs/widget_type_contract.md`. По нему поля входа только добавляются, а смысл и тип существующих не меняются. Варианты:

- **Отдельное поле с точным значением.** Например, `inputs.<port>.raw` — исходная строка значения для всех TagType. `value` остаётся `number`, а виджету, которому нужна точность, хватит `BigInt(inputs.n.raw)`. Контракт не ломается, это расширение.
- **Строка вместо числа для больших значений.** Простой фикс, но тип `value` начинает зависеть от величины числа, а контракт обещает `number` для Integer. Нарушает контракт.
- **`BigInt` для больших значений.** Точно, но `JSON.parse` не создаёт `BigInt` (нужен свой разбор в `liveWidgetTail` и в `BuildSrcdoc`), а смешивать `BigInt` с `number` в арифметике нельзя: `value + 1` бросит `TypeError`. Нарушает контракт.
- **Оставить как есть.** Записать ограничение в контракт: Integer точен до ±(2^53 − 1). Опционально: вне диапазона помечать порт как Uncertain.

## Приёмка (для варианта, который выберем)

- `docs/widget_type_contract.md` описывает, что виджет получает для Integer вне безопасного диапазона.
- Юнит-тест в `uiutil` на значения на границе: `9007199254740991`, `9007199254740993`, `-9007199254740993`, `math.MaxInt64`, `math.MinInt64`.
- Проверка в браузере: виджет с Integer-тегом `9007199254740993` в Operation и в превью Project ведёт себя так, как описано в контракте.
- `make build` и `make test` проходят.

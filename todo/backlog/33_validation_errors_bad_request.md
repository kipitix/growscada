# Ошибки валидации ввода → 400 Bad Request

Сейчас REST API отвечает 400 только на невалидный JSON или UUID в пути. Любая ошибка разбора/валидации доменных значений (имя тега, значение, `TagType`, `TagQuality`, `ScriptLanguage`, `PortTypeHint`, размеры и т. п.) уходит в 500 — это прямо зафиксировано тестом `TestPostTags_InvalidType_Returns500WithProblemDetails`.

- Ввести в application-слое общий способ пометить ошибку как «невалидный ввод» (sentinel или тип ошибки), оборачивать им ошибки разбора и валидации в сервисах.
- Во всех хендлерах маппить такие ошибки в 400 (`NewBadRequest`), остальные — по-прежнему в 500.
- Обновить тесты, ожидающие 500 на невалидный ввод, и `CHANGELOG.md`.
- Проверить Bruno-коллекции (ожидаемые статусы, если где-то указаны).
- Появилось в ходе задачи 13: `"quality": "simulated"` и `"type_hint": "unknown"` сейчас отклоняются с 500.

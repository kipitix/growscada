# Страница выбора библиотек: две панели, инлайн-имя и описание, порядок перетаскиванием

Status: needs-triage
Priority: 2
Blocked by: 81

Дизайн согласован грилингом 2026-11-12; серверная часть — задача 81
(`/api/v0/settings/library-order`, ADR 0024). Заменяет нынешнюю страницу
выбора (`ui/picker`) для Library и Project: список, диалог Name+Description
и кнопки Open/Edit/Delete уходят.

## Раскладка

- Десктоп (порог ~720–760 px): слева список (260–280 px, свой скролл),
  справа детали. Список — только имена, выбранная строка — фон
  `--accent`/текст `--accent-text`. Справа: имя (h2), описание, состояние
  («Unsaved changes» и пр.), кнопки.
- Мобильный: те же две области двумя экранами (список → детали, назад
  «← Libraries»), не две колонки. Возврат из редактора — детали той же
  библиотеки; удалённой/404 — список (задача 76).
- Адаптив: inline-стили перебивают медиазапросы, поэтому layout-свойства
  нескольких узлов — в инжектированный `<style>` по `data-picker-*`
  с `!important` (или классы вместо inline), а не ветвление по
  `app.Window().Size()`.
- Клик = выбор, не открытие. Редактор виджетов — кнопка «Открыть» в
  деталях. `OnDblClick` строки больше не открывает редактор.

## Редактирование

- Двойной клик по имени/описанию (десктоп) или карандаш (мобильный) —
  инлайн-поле. Enter сохраняет имя; описание — `textarea`, Enter = перенос,
  Ctrl/Cmd+Enter сохраняет; blur сохраняет оба; Esc отменяет. На мобильном
  Esc нет — нужна видимая кнопка отмены рядом с полем; поле получает
  `AutoFocus`, кнопки деталей остаются в потоке (не `fixed`).
- Оба поля пишутся одним `PUT /libraries/{id}` с текущей парой и версией.
  Ничего не изменилось → запроса нет. Ошибка (имя занято, 409) → поле
  остаётся в редактировании, текст сохраняется, отказ показывается под
  полем (`role="alert"`, `problemText`); 409-версия перечитывает строку и
  не перезаписывает молча.
- Двойного коммита нет (Enter → перерисовка → blur): флаг «сохраняем» и
  сравнение с исходным значением.
- Действия деталей ждут незавершённую запись (как PATCH стрелок в
  Project): ответ по «своей» библиотеке не применяется к другой
  (задача 61).
- Иконки: инлайновые SVG 16 px, `currentColor`, `aria-hidden`,
  `data-icon`; `title` + `aria-label`. Только однозначные действия
  (плюс, карандаш, корзина, ручка, стрелки) — без текста на десктопе; на
  мобильном иконка + подпись. Save/Cancel и подтверждение удаления —
  текстом. Tap-to-tooltip и long-press-tooltip не делать.

## Создание

- «＋» в шапке списка (десктоп 36 px, мобильный 44×44); пустой список —
  CTA «Создать первую библиотеку» в деталях.
- Без диалога и без формы: «＋» добавляет черновую строку, детали
  переключаются в режим создания с полем имени в фокусе; Enter/blur с
  непустым именем → `POST`; пустое имя → черновик исчезает без запроса;
  отказ сервера — в поле.
- Бейдж состояния остаётся: точка у имени в списке (`title` с текстом) +
  полный бейдж в деталях.

## Порядок

- Десктоп: перетаскивание только за ручку `⋮⋮` (нативный HTML5 DnD, как
  WidgetType → сцена), линия-индикатор между строками, `Alt+↑/↓` для
  клавиатуры.
- Мобильный: go-app v11 **не отдаёт touch/pointer-события** (только mouse,
  drag, key, input) — перетаскивание требует JS-интеропа:
  `app.Window().Call("addEventListener", "pointerdown", js.FuncOf(...))` в
  файле `//go:build js && wasm` плюс заглушка для хоста. Long-press 400 мс
  без смещения > 8 px, «поднятая» строка, `touch-action: none` только на
  захваченной строке, авто-скролл в 60 px от краёв, вибрация через
  `navigator.vibrate`.
- Обе проводки зовут одну чистую функцию `move(ids, from, to)`; она, порог
  и расчёт индекса по Y — обычный Go с тестами. Проводка событий тестами
  на хосте не покрывается: проверяется вручную в браузере и на телефоне.
- Оптимистично применить, затем `PUT` полного слитого массива; ошибка
  сети/409 → откат к прежнему порядку + toast.
- Слияние: сохранённые ID первыми (только живые), затем остальные по
  имени. `picker.load` перестаёт сортировать по имени — иначе ручной
  порядок стирается на каждом событии.

## Тесты и проверки

- `data-picker-*` хуки сохранить; состояние — методами (`startEdit`,
  `commitEdit`, `cancelEdit`, `createDraft`, `move`), как сейчас
  `submitDialog`/`doDelete`, потому что тесты монтируют компонент на хосте.
- Тесты: commit по blur, Esc/отмена, «ничего не изменилось», 409, порядок
  и слияние, создание черновой строкой.
- `make build`, `make test`, `make bruno_test`, ручной проход в PWA на
  десктопе и в мобильной эмуляции (консоль без ошибок).

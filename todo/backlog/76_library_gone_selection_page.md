# 404 выбранной Library не сообщает Root: вкладка остаётся на пустом редакторе

Status: needs-triage
Priority: 3

Появилось при ревью задачи 73 (находка Bugs 4). У Library нет канала,
которым компонент сообщает Root, что выбранная сущность исчезла:
`ui/library/load.go` `libraryGone` сбрасывает выбор внутри компонента
(`selectLibrary(ctx, uuid.Nil)`), но `Root.showList` остаётся `false`, и
вкладка может остаться на пустом редакторе вместо страницы выбора.

У Project для этого есть `uiutil.ActionProjectGone` (его шлют 404 списка
Scene/Tag и 404 `GET …/operation`); у Library аналога нет. Реалистичные пути
сегодня закрыты событиями (`library_deleted`) и `reconcile` страницы выбора,
поэтому находка низкого приоритета, но пробел настоящий: удаление из другой
вкладки при потерянном событии или стухший ключ `library:selectedLibrary`
оставляют пользователя на пустом экране.

## Задача

Дать Library тот же путь «сущность исчезла», что у Project, и перевести Root
на страницу выбора.

## Варианты решения (выбрать один)

1. Новый action `uiutil.ActionLibraryGone` по образцу `ActionProjectGone`:
   `libraryGone` шлёт его вместо локального сброса, Root ловит и показывает
   список. Сохраняет общий механизм двух режимов.
2. Колбэк `Root`: `Library` получает `OnGone func()`, Root переключает
   `showList` и обнуляет выбранную библиотеку. Проще, но расходится с тем, как
   это сделано у Project.

## Приёмка

1. Удаление выбранной Library в другой вкладке (событие потеряно) или стухший
   `library:selectedLibrary` при открытии вкладки оставляют пользователя на
   странице выбора, а не на пустом редакторе.
2. `← Список · <имя>` и выбор другой Library после этого работают.
3. Тест: 404 Draft'а или Releases выбранной Library переводит Root на список.
4. `make build`, `make test` зелёные.

## Связанное

- Задача 73 — страницы выбора и слим-строка возврата.
- `uiutil.ActionProjectGone` — существующий аналог для Project.

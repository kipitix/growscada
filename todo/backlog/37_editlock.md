## Модель

- **EditLock** — маркерный агрегат инженерного узла: одна строка на Draft (проекта или Library) в `engineering.edit_locks`. Две nullable FK — `project_id → projects` и `library_id → engineering.libraries` — с CHECK «ровно одна», обе `ON DELETE CASCADE`, частичные уникальные индексы. Строка остаётся и при свободном замке: её `version` растёт монотонно (взятие, отпускание, перехват, истечение), поэтому клиент отличает устаревшее наблюдение от свежего. Обновление `last_seen` версию не поднимает.
- **Держатель — Client**: ключ (UUID, который вкладка держит в `sessionStorage`; переживает перезагрузку, у новой вкладки свой) и добровольно указанное имя. Ключ идёт заголовком `X-GrowSCADA-Client` во всех гейтованных запросах и параметром `?client=` в SSE-потоке. Это координация, а не аутентификация: имя не проверяется, ключ не секрет, перехват доступен любому клиенту. С приходом User (49) держателем станет User, а ключ — его идентификатором в запросе.
- **Живость**: замок жив, пока к серверу привязан SSE-поток с ключом держателя (presence в памяти инженерного узла, refcount соединений), либо пока с последнего запроса с этим ключом прошло меньше константы `editLockTTL = 5 мин`. Reaper раз в 30 с: присутствующему держателю обновляет `last_seen`, отсутствующего с `last_seen` старше TTL освобождает с `edit_lock_expired`. Обновление `last_seen` при присутствии делает перезапуск сервера безвредным: вкладка переподключается в пределах TTL и замок сохраняется. Клиент без SSE (growctl, Bruno) живёт своими записями и теряет замок через 5 минут после последней.
- **Гейт**: все записи содержимого Draft (определения Tag, Scenes с Widgets, Devices, Environments и их пары, Library Pins, WidgetTypes) и акты над Draft целиком — Deploy, Release, Discard. Вне гейта: запись значений Tag (`PATCH …/value`), Device Token, создание/переименование/удаление Project и Library, Rollback (Runtime-узел, Draft не читает, ADR 0014).
- **Проверка — в транзакции записи**: репозиторий области читает строку держателя `FOR SHARE` в той же транзакции, что и запись, и отказывает `ErrEditLockNotHeld` (409; текущий держатель — в Problem Details) до изменения. Перехват пишет ту же строку, поэтому сериализуется с записью: правка, начатая до перехвата, успевает, начатая после — получает 409. Release и Discard проверяют замок в транзакции своей записи (релизных строк и пометки Discard); Deploy, сборка ProjectFile которого идёт несколькими запросами и одной транзакции не имеет, — перед сборкой. Политики (Discard, очистка Project и Library, согласование Widgets, снятие привязок) пишут как `System` и проверку не проходят.
- **Взятие, отдача, перехват**: Check out свободного замка — 201 и состояние с новой `version`; занятого — 409 с держателем; тем же ключом — 200 (идемпотентно). Check in держателем — 200 (свободный замок — 200, идемпотентно; чужой — 409). Перехват — только занятого, с `expected_version` из последнего GET/события: устарела — 409, клиент перечитывает состояние; свой же замок — 200 без изменений. Check out отклоняется, пока идёт Discard области (409, как у записи).
- **События**: `edit_lock_acquired`, `edit_lock_released`, `edit_lock_taken_over`, `edit_lock_expired`; у Draft проекта — в поток проекта, у Draft Library — в серверный поток. Payload несёт состояние замка (держатель, `since`, `version`). Check in ничего не публикует из Draft (ни Deploy, ни Release), не сбрасывает Draft и (когда появится, задача 38) стек undo.
- **UI**: в шапке Project и Library — строка замка: `Check out` (спрашивает имя один раз, дальше запоминает в LocalStorage) когда свободен; `Editing as <name> — Check in` когда держишь; `<name> is editing since HH:MM — Take over` когда держит другой. Без замка весь Draft — только для чтения: кнопки правки и Deploy/Discard (Project), Release/Discard (Library) видны, но выключены с подсказкой; Deploy/Discard/Release проверяются сервером так же. Потеря замка (перехват или истечение) — toast и read-only. При переключении на другой Project (или Library) UI сразу шлёт Check in прежнему. Ключ вкладки — в `sessionStorage`, имя — в `LocalStorage`.
- **growctl и Bruno — по общему протоколу**: Check out с собственным ключом и именем, правки с заголовком, Check in в конце. growctl берёт замок вокруг мутирующего прогона (ключ на запуск, имя — флагом или по умолчанию), при занятом замке — ошибка с именем держателя, форс — отдельным флагом. Bruno — setup- и teardown-запросы коллекции.
- **Контракт `api/v0` — MINOR** (`make schemas`): заголовок клиента и параметр SSE, `EditLockResponse` (held, держатель с именем и `since`, version), тела Check out/перехвата, четыре маршрута на область (`GET …/edit-lock`, `POST …/edit-lock`, `DELETE …/edit-lock`, `POST …/edit-lock/takeover`), поле `edit_lock` в `Problem`, четыре имени событий.
- **Инфраструктура**: миграция `engineering.20261105000000_edit_locks`; `domain/editlock` в `engineeringRole` (`roles_test`); сервис и reaper в `main.go`; SSE-обработчик привязывает и отвязывает ключ; `apiclient.WithClientKey` и методы замка; `contract/api/v0` и схемы.
- **Тесты**: репозиторий (взятие, занятый замок, перехват с устаревшей version, истечение, presence, CASCADE), REST (четыре маршрута, 409 с держателем, 400 без ключа, 404), сервисные (гейт каждой записи Draft, политики как `System`, Deploy/Release/Discard), UI (read-only, строка замка, перехват, toast, Check in при переключении), Bruno (новые маршруты и порядок), growctl.
- **Документы**: ADR 0015, `GLOSSARY.md` (Client, Check out, Check in, EditLock), `CHANGELOG.md`, `AGENTS.md` (маршруты, строка замка, режим чтения).

## Разбиение

- **37_1 — Draft проекта.** Вся механика (агрегат, миграция, presence, reaper, REST, события, контракт, apiclient) и её область Project: проверка в записях Project, Deploy и Discard, UI Project-режима, growctl и Bruno для проекта, тесты. После неё Project правится только под замком, Library — как раньше.
- **37_2 — Draft Library.** Маршруты и события Library-области, проверка в записях WidgetType, Release и Discard Library, UI Library-режима, growctl (library) и Bruno (library), тесты. Блокирована 37_1: механика уже есть, добавляется вторая область.

Закрытие: 37_2 помечена `Closes parent: yes` — когда она уходит в `todo/done/` и остальные части цепочки там же, `/kx_done` переносит и этот файл.

- 2026-11-05 (grilling, ADR 0015). Решения:
  - Держатель — ключ вкладки (sessionStorage) плюс имя; живость — присутствие SSE с этим ключом или запрос с ним за 5 минут; presence в памяти узла, reaper обновляет `last_seen` присутствующим и освобождает отсутствующих через TTL. Клиенты без SSE живут записями и TTL.
  - Гейт — содержимое Draft плюс Deploy/Release/Discard; вне гейта значения Tag, Device Token, создание/переименование/удаление Project и Library, Rollback.
  - Проверка — в транзакции записи (репозиторий области читает строку `FOR SHARE`); Release/Discard — в транзакции своей записи, Deploy — перед сборкой ProjectFile; политики — `System`. Ключ приходит заголовком и кладётся в context как идентичность запроса (в отличие от `project_id`, ошибка «забыли» отказывает, а не утекает).
  - Перехват — только занятого замка и с observed version; событие `edit_lock_taken_over`, прежний держатель по своему ключу понимает, что больше не держит, и переходит в read-only.
  - Отказ без замка — 409 Problem Details с текущим держателем; без ключа — 400.
  - UI: строка замка в шапке, явный Check out, всё остальное read-only; переключение Project/Library шлёт Check in прежнему.
  - Состояние — таблица `engineering.edit_locks`, а не память и не поля Project/Library: переживает перезапуск, в задаче 38 станет полем агрегата Draft.
  - growctl и Bruno берут замок сами по общему протоколу; исключения для автоматизации нет.
  - Разбиение по областям, а не сервер/UI: после 37_1 приложение остаётся рабочим (Project под замком, Library — нет), после 37_2 — целиком. Разрез «сервер, потом UI» отвергнут: между частями UI не смог бы править вообще.

# Лишние перезагрузки UI на события библиотек
Status: needs-triage

Появилось при ревью задачи 33 (находки №8 и №9). На события библиотек и их WidgetTypes режимы Library и Project перезагружают больше, чем им нужно, и объём растёт вместе с числом релизов.

- **Режим Library** (`ui/library/server_events.go`). `eventlog.ReloadTargetsFor` выставляет `Libraries` на каждое `library_*` и `widget_type_*`, и режим перезагружает `GET /libraries/{id}/releases`, то есть все релизы с полными `html_template` и `script` всех WidgetTypes. Каждый Apply в редакторе (`widget_type_updated`) и каждое событие другой библиотеки скачивает все копии заново: при 20 релизах по 30 типов это 600 копий с SVG. `loadList` при этом срабатывает и на события чужих библиотек.
- **Режим Project** (`ui/project/server_events.go`). Режиму нужны только имена библиотек и номера последних релизов, но он перезагружает `GET /libraries` на каждое `widget_type_*`. Сервер для каждой библиотеки сравнивает Draft с последним релизом (`library.ReleaseStateOf`: Draft и последний релиз читаются целиком), хотя Draft проекту не виден.

Требования:
- Для истории релизов хватает номера, заметки и даты. Содержимое (WidgetTypes) грузится только для релиза, который открыт на просмотр: отдельный список релизов без содержимого в API или чтение одного релиза по номеру (`GET …/releases/{n}` уже есть).
- Режим Library перезагружает релизы и Draft только на события своей библиотеки (`library_id` в событии) и только то, что событие могло изменить: `library_released` — релизы, `widget_type_*` — Draft и признак «unreleased changes».
- Режим Project не перезагружает библиотеки на `widget_type_*`: ему важны `library_*` (имя, удаление, новый релиз).
- Если признак «unreleased changes» в `GET /libraries` останется дорогим, решить, нужен ли он в списке, или вынести его в чтение одной библиотеки. Считать его по-прежнему должна одна доменная функция `DraftDiffers`, без SQL-копии.
- Тесты UI (`uitest`): Apply в редакторе не перезагружает релизы, событие другой библиотеки не трогает выбранную.

# Добавить в клиент минимальный функционал режима Operation
Status: ready-for-agent

Проработка по итогам grilling-сессий 2026-09-28 и 2026-09-29. Сейчас `internal/server/interface/ui/operation/operation.go` — заглушка. Это временный Operation поверх текущих таблиц и SSE, без Revision и Journal: в тикете 36/08 (Player) источник данных заменится на Revision + Journal, а рендер Scene с живыми значениями переиспользуется.

## Поведение

- Только наблюдение: Operator ничего не пишет, виджеты неинтерактивны. Управление процессом — задача 25 (Command).
- Навигация — вкладки со всеми Scene, как в Project (тот же порядок), но без создания, удаления и переименования: только переключение. Выбранная вкладка запоминается в LocalStorage (`operation:sceneID`); если её Scene удалена — выбирается первая.
- Холст Scene — 1:1 с прокруткой, как в Project, но без точечной сетки редактора. Под виджетами рендерится `background_html` Scene в sandboxed iframe (пустой — однотонный фон).
- Виджет получает в `inputs` текущие значения привязанных Tag: `inputs.<port>.value` (см. «Контракт WidgetType» ниже). Значение конвертируется по TagType привязанного Tag, а не по type hint порта: для порта `any`, привязанного к Integer, приходит число, а не строка. Если у InputPort нет PortBinding или привязанный Tag удалён — дефолт по type hint порта (как `uiutil.PortValueToJS` для пустого значения; для `any` — `undefined`), и порт для индикации считается `Bad` в обоих случаях: недонастроенный виджет должен быть заметен.
- Quality показывает Operation, а не виджет: поверх виджета — маркер худшей Quality среди его портов. `Uncertain` — жёлтая рамка, `Bad` — красная рамка с затемнением, `Good` — без маркера. Quality в `inputs` пока не передаётся.
- Изменения конфигурации (Scene, Widget, WidgetType, создание/удаление Tag — из Project, другой вкладки, `growctl`) подхватываются на лету, как в Project. Временно: после Deploy (36/03, 36/08) Operation будет следовать только за Revision.
- Разрыв SSE: над Scene — плашка «Нет связи с сервером», все виджеты получают маркер `Uncertain`. После переподключения (`onopen`) заново загружаются теги и конфигурация — replay событий нет, пропущенные значения иначе потеряются. Для этого `eventlog.Bar` сообщает о потере и восстановлении связи — go-app state `eventlog.StateDisconnected`, а не action: Operation, открытый уже во время разрыва, должен сразу знать текущее состояние. Chrome переводит `EventSource` в `CLOSED`, когда сервер пропадает посреди потока, и сам больше не переподключается, поэтому `Bar` в этом случае пересоздаёт соединение каждые 2 с.

## Сервер: `tag_updated` несёт состояние тега

- SSE-сообщение `tag_updated` получает вложенное поле `tag` в той же JSON-форме, что `GET /api/v1/tags/{id}` (restdto: id, name, type, value, quality, version). Остальные события не меняются. Это форма «толстого» события из тикета 36/02, пока только для `tag_updated`.
- Состояние передаётся через доменное событие `TagUpdatedEvent` (его публикует `SetTagValueByID`), `event_hub` сериализует его в `eventMessage`.
- Обновить тесты `restapi/events_test.go` и Bruno `get_events.yml` (docs/пример сообщения).
- Operation применяет значение из события, не делая `GET` тега.
- Слияние состояния тегов — по Version: и при применении `tag_updated`, и при загрузке списка для каждого Tag остаётся состояние с большей Version (ответ `GET /tags`, собранный до события, не откатывает значение). Состав тегов задаёт последний загруженный список; `tag_updated` для неизвестного Tag добавляет его (событие несёт полное состояние).

## Контракт WidgetType

- `inputs` — объект по именам InputPort, каждый вход — объект: `inputs.speed.value`. Сейчас у входа только `value`; новые поля (`quality` и т.п.) добавляются только аддитивно, форма существующих полей не меняется. Это ломающее изменение для текущих скриптов: переписать примеры в `internal/server/infrastructure/postgres/test_data/20990101000000_insert_test_data.sql` (`inputs.x` → `inputs.x.value`). `BuildSrcdoc` (Library, Project) формирует `inputs` в той же форме.
- `render(inputs)` может вызываться многократно и должен быть идемпотентным.
- Контракт описать в новом `docs/widget_type_contract.md` (для авторов WidgetType): глобальная `render(inputs)`, форма `inputs` и правило аддитивного расширения, типы значений по TagType и дефолты для непривязанных портов, идемпотентность, песочница (CSP `connect-src 'none'` — сеть из виджета недоступна, Quality показывает Operation). Doc-комментарий `BuildSrcdoc` ссылается на этот документ.

## Обновление виджетов

- iframe виджета создаётся один раз. Новые значения доставляются через `postMessage` конвертом `{type: "inputs", inputs: {...}}` (конверт — чтобы позже добавлять типы сообщений без смены протокола): srcdoc содержит обработчик `message`, который вызывает `render(inputs)` со свежими значениями. Без перезагрузки iframe — нет мерцания, анимации виджета не сбрасываются.
- Handshake: после загрузки iframe шлёт родителю `{type: "ready"}`, Operation в ответ отправляет актуальные `inputs`. До `ready` сообщения в этот iframe не шлются — значения, изменившиеся во время загрузки srcdoc, не теряются.
- iframe пересоздаётся (новый srcdoc) только при смене кода: HTML, script или списка InputPort у WidgetType, либо смене WidgetType у Widget. Позиция, размер, поворот и смена PortBinding меняют только стиль или `inputs` (через `postMessage`).
- Проверять источник сообщения (только родительское окно) и не доверять содержимому сверх того, что уже делает `BuildSrcdoc` (экранирование, CSP `connect-src 'none'`).
- Project остаётся на пересборке srcdoc — переводить его на `postMessage` не требуется.

## Структура кода

- Компонент «Scene с живыми значениями» принимает готовое состояние (Scene, её Widgets, WidgetTypes, значения и Quality тегов, признак связи) и сам ничего не загружает — это то, что переиспользует Player в 36/08.
- Загрузка списков, подписка на SSE и применение событий живут в пакете `operation`. Загрузчики — по образцу Project (`uiutil.Reloader`); обобщение загрузчиков и таблицы «событие → что перезагружать» — задача 37.
- Чистые функции покрыть unit-тестами: вычисление `inputs` виджета из PortBindings и тегов (включая конвертацию по TagType для порта `any`), слияние состояния тегов по Version, худшая Quality с учётом непривязанных портов и разрыва связи, применение `tag_updated` к состоянию тегов, маршрутизация событий.

## Приёмка

- `make full_restart`, затем `make run_simulator_dashboard`: в Operation на вкладке «Main Dashboard» спидометр, индикатор и бегущая строка меняются в реальном времени без мерцания.
- Изменение значения/Quality тега через Bruno (`patch_tag_value`) видно в Operation; `bad`/`uncertain` дают соответствующий маркер.
- Правка Scene или Widget в Project (другая вкладка) появляется в Operation без перезагрузки страницы.
- Остановка сервера → плашка «Нет связи» и маркеры `Uncertain`; после запуска значения и конфигурация восстанавливаются сами.
- Превью в Library и Project работают с новой формой `inputs` (seed-виджеты рисуются как раньше).
- Проверить в браузере через chrome-devtools; `make build` и `make test` проходят.

## Что сделать

### `devicelink` — без изменений контракта

ADR 0004 цела: `Link` остаётся `Resolve` + `Write`. **Меняется только то, как Link получает доступ:**
- `devicelink.NewRESTLink(client, projectName)` → токен вместо имени проекта: проект определяется токеном (CONTEXT.md), имя проекта больше не передаётся.
- `RESTLink` шлёт `Authorization: Bearer <token>`; `Resolve` ищет Tag по имени в проекте токена.
- `Resolve`/`Write` — те же пути REST, что и сегодня.

### Конфиг симулятора

- Вместо `project:` — `token:` и `environment:` (имя или ID окружения), плюс прежние `server`, `control`, `autostart`, `defaultInterval`, `tags`.
- Симулятор — **одно** окружение; паттерны — параметры Device (протокол `simulation`), то есть конфиг симулятора описывает Device, а не «проект с тегами».
- Строгий разбор YAML, неизвестные поля — ошибка (как сейчас).

### Получение конфигурации

- Симулятор **получает конфигурацию у сервера** по своему токену: `GET /api/v0/device/config?environment=<id>` — Device, окружение, параметры связи и список её Tag'ов (`id`, `name`, `type`).
- Значит, симулятор **не знает** список Tag'ов заранее: он берёт его из конфигурации, а локальный конфиг задаёт, что и как писать (паттерн на Tag по имени).
- Ошибка «токен неизвестен» (401) и «писать нельзя» (403) — по правилам части 4.

### Коды выхода (`cmd/device_simulator`)

Развести коды, как требует задача 34:

| Ситуация | Код |
|---|---|
| `401`, `403` (неверный/отозванный токен, нет прав) | `ExitNoPerm` (77) |
| прочие `4xx` | `ExitProtocol` (76) |
| ошибка TLS, неверная схема URL | `ExitProtocol` (76) |
| тег не найден, несовместимый паттерн, ошибка конфига | `ExitConfig` (78) |
| файл конфига отсутствует | `ExitNoInput` (66) — как сейчас |

Сегодня **любая** нетранзиентная ошибка резолва даёт `ExitConfig` (78) — это и надо исправить. Транзиентные (сеть, `5xx`) — как сейчас: повтор при старте, пропуск до следующего тика.

### SSE для Gateway

- Симулятор может подписаться на `GET /api/v0/device/events` (SSE по токену), чтобы узнать об изменении конфигурации и об отзыве/ротации токена; при обрыве — переподключение и перечитывание конфигурации.
- Обязательно: **перечитывание конфигурации** при изменении (паттерны/состав Tag'ов обновляются).

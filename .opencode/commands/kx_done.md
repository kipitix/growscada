description: Закрыть задачу — проверить стадии, тесты, перенос в done и влить ветку в path
---

Закрой текущую задачу: проверь, что она действительно доведена, и влей ветку в `path`.

1. Ветка: `git branch --show-current`. Это `path` — закрывать нечего, кроме задачи, которая сделана только документами прямо на `path`: тогда возьми её из `$ARGUMENTS`, пропусти вливание (шаг 8) и выполни остальные шаги; без аргумента остановись и скажи, что закрывать нечего.
2. Определи задачу: по имени ветки `<NN>_<slug>`, на `path` — по `$ARGUMENTS`. Её файл — `todo/done/<NN>_<slug>.md` (или ещё `todo/backlog/<NN>_<slug>.md`). Нет ни там ни там — остановись.
3. Сверь стадии по `git log path..HEAD --oneline` и по файлу задачи, каждую отметь «пройдена / не видно» с доказательством (хэш коммита, файл):
   - **grilling** — коммит `... grilling`, решения в задаче или ADR, `Status: ready-for-agent`;
   - **code** — коммиты задачи с изменениями в `internal/`, `contract/`, `cmd/`, `docs/`; у задачи только из документов — изменения в `todo/`, `docs/`, `GLOSSARY.md`;
   - **review** — коммиты `... review:` или отчёт ревью в сессии;
   - **fix** — правки после ревью либо явное «ревью без находок».
   Чего-то не видно — спроси, а не достраивай за пользователя.
4. Тесты и проверки (правило 3 и правило 9 `AGENTS.md`): `make build`, `make test`, `make bruno_test`; если задача трогает UI — подними окружение (правило 6), пройди затронутые экраны в браузере, консоль без ошибок. Любой красный результат — стоп, задачу не закрывай.
5. Файл задачи должен лежать в `todo/done/`: ещё в backlog — перенеси `git mv` (имя не меняется). Если в задаче остались невыполненные пункты — скажи и не закрывай. Если у задачи стоит `Closes parent: yes` (последняя часть цепочки, `/kx_grill` шаг 8), перенеси `git mv` и родительский файл из строки `Parent:` — но только когда все остальные части (`Part: k/m`) уже в `todo/done/`; иначе скажи, какие части открыты, и родителя не переноси. Обратно: родителя со строкой `Parts:` не закрывай, пока хоть одна его часть не в `todo/done/`.
6. Грязное дерево — закоммить по правилам `/kx_commit` (сообщение в стиле истории, без push).
7. `CHANGELOG.md`: по истории репозитория каждая задача добавляет запись и поднимает версию. Записи о задаче нет — спроси, добавить ли, прежде чем вливать.
8. Вливание: в ветке — `git switch path`, затем `git merge --ff-only <ветка>`. Fast-forward не выходит (path ушёл вперёд) — вернись в ветку, `git rebase path`, повтори тесты из шага 4 и снова влей; если расхождение спорное — спроси. На `path` (задача только из документов) вливания нет. Ветку не удаляй и не пушь без просьбы.
9. Покажи результат: `git log --oneline -3`, `git status --short`, и список того, что осталось за кадром (push, удаление ветки, релиз).
10. Отправь уведомление в ntfy по правилу 11 `AGENTS.md`.

Аргументы: если передан текст — $ARGUMENTS — это ветка или номер задачи, если не хочешь брать текущую.

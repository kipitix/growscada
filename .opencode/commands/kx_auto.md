Реализуй подряд все задачи со `Status: ready-for-agent`, пока не упрёшься в задачу, не готовую для агента. На каждую задачу — три **чистые сессии** (`subagent`, `agent: general`, последовательно, не параллельно):

1. `kx_branch` — ветка;
2. `kx_code` — реализация;
3. одна сессия `kx_review` → `kx_fix` → `kx_done`.

Человека в цикле нет: вопросы не задаются, на каждой развилке выбирается рекомендованный вариант. Код, коммиты и слияние делает не эта сессия, а подсессии; сама она только оркестрирует, проверяет результат и ведёт отчёт.

## Подготовка

1. `git status --short`. Дерево грязное — остановись и покажи, что мешает: чужие правки в конвейер не тащи.
2. `git branch --show-current`. Не `path` — при чистом дереве переключись: `git switch path`. Это точка старта каждого цикла.
3. Проверь, что `todo/backlog/` и `todo/done/` существуют. Нет — остановись.
4. Влей спеки. После `/kx_grill`, разбившего задачу на части, родитель-спека и его части живут в ветке задачи, а не в `path`; пока их там нет, очередь видит только старый файл и останавливается. Просмотри локальные ветки:

   ```bash
   for b in $(git for-each-ref --format='%(refname:short)' refs/heads); do
     [ "$b" = path ] && continue
     git merge-base --is-ancestor "$b" path 2>/dev/null && continue      # уже в path
     if git merge-base --is-ancestor path "$b" 2>/dev/null; then
       echo "FF   $b"
     elif git diff --name-only "path...${b}" | grep -qEv '^(todo/|docs/adr/|GLOSSARY\.md|AGENTS\.md|CHANGELOG\.md)'; then
       echo "CODE $b"                                                    # трогает код — не вливать
     else
       echo "SPEC $b"                                                    # только документы — можно ребейзить
     fi
   done
   ```

   `FF` — `git merge --ff-only`. `SPEC` — ветка разошлась с `path`, но меняет только `todo/`, `docs/adr/` и корневые `*.md`: `git rebase path` в ветке, повтори проверку diff'а и `git merge --ff-only`. Это подготовка документов, а не работа над задачей: кода такая ветка не трогает. `CODE` — незакрытая задача с кодом: покажи ветку и остановись, её разбирает человек.

## Выбор задачи

В начале каждой итерации (уже на `path` с чистым деревом) выполни:

```bash
cd "$(git rev-parse --show-toplevel)"
for f in $(find todo/backlog -maxdepth 1 -name '*.md' | sort -V); do
  # Родитель со строкой Parts: — спецификация, а не работа: пропусти и проверь, что части на месте.
  if grep -q '^Parts:' "$f"; then
    echo "SKIP parent: $f"
    missing=""
    for p in $(grep -m1 '^Parts:' "$f" | sed 's/^Parts:[[:space:]]*//' | tr ',' ' '); do
      if compgen -G "todo/backlog/${p}.md" >/dev/null || compgen -G "todo/done/${p}.md" >/dev/null; then
        :
      else
        missing="$missing $p"
      fi
    done
    if [ -n "$missing" ]; then
      echo "NEXT="; echo "STOP=у родителя $(basename "$f") нет частей:${missing} (спека не влита?)"; exit 0
    fi
    continue
  fi
  status=$(grep -m1 '^Status:' "$f" | sed 's/^Status:[[:space:]]*//' || true)
  blocked=$(grep -m1 '^Blocked by:' "$f" | sed 's/^Blocked by:[[:space:]]*//' || true)
  open_blockers=""
  if [ -n "$blocked" ]; then
    for b in $(echo "$blocked" | tr ',' ' '); do
      if compgen -G "todo/done/${b}.md" >/dev/null || compgen -G "todo/done/${b}_*.md" >/dev/null; then
        :
      else
        open_blockers="$open_blockers $b"
      fi
    done
  fi
  # Спроектированная версия задачи могла остаться в невлитой ветке: тогда STOP — не приговор, а подсказка.
  hint=""
  for br in $(git for-each-ref --format='%(refname:short)' refs/heads); do
    [ "$br" = path ] && continue
    git merge-base --is-ancestor "$br" path 2>/dev/null && continue
    if git show "${br}:${f}" 2>/dev/null | grep -q '^Status: ready-for-agent'; then
      hint="$hint $br"
    fi
  done
  suffix="${hint:+ (спроектирована в ветке:${hint} — влить)}"
  if [ -n "$open_blockers" ]; then
    echo "NEXT="; echo "STOP=задача $(basename "$f") заблокирована:${open_blockers}${suffix}"; exit 0
  fi
  if [ "$status" != "ready-for-agent" ]; then
    echo "NEXT="; echo "STOP=задача $(basename "$f") не готова для агента (Status: ${status:-<нет>})${suffix}"; exit 0
  fi
  echo "NEXT=$f"; exit 0
done
echo "NEXT="; echo "STOP=в backlog не осталось задач"
```

Родительские файлы со строкой `Parts:` — спецификации, а не работа: они пропускаются при любом `Status`, а очередь идёт по частям (`NN_1_…`, `NN_2_…`); части без файла в `backlog`/`done` — остановка, это невлитая спека. Останавливайся именно на первой задаче по номеру: не перескакивай через заблокированную или неготовую к более поздней — порядок и есть очередь. Подсказка «спроектирована в ветке» означает, что задача уже прогрилена, но ветка не влита в `path`: влей её по шагу 4 подготовки, а не перескакивай задачу.

`NEXT` пуст — цикл закончен: покажи причину из `STOP` и переходи к итогу.

Держи счётчик закрытых задач. Если `$ARGUMENTS` — целое число, это предел задач за прогон: счётчик дошёл до него — остановись и переходи к итогу.

Дальше повторяй три стадии, пока цикл не остановится. Один `subagent` за раз, foreground: стадии идут строго последовательно, следующая задача не начинается, пока предыдущая не влита в `path`.

## Стадия 1 — ветка

Запусти один `subagent` (`agent: general`, foreground) с промптом:

> Ты — стадия `kx_branch` автоматического конвейера `/kx_auto`, чистая сессия. Прочитай `.opencode/commands/kx_branch.md` и выполни её шаги полностью для задачи `<NEXT>`. Человека нет: не задавай вопросов и не вызывай AskUserQuestion; на каждой развилке бери рекомендованный вариант, при его отсутствии — наиболее консервативный, не противоречащий `docs/adr/`. Забытый хвост, который шаг 2 команды нашёл (работа закончена, а файл в backlog), перенеси `git mv` в `todo/done/` сам. Решение и причину занеси в отчёт. Уведомление в ntfy не отправляй — его отправит `kx_auto`. Кода и грилинга не делай: только ветка. Верни: имя ветки, файл задачи, её Status, следующий шаг и принятые решения.

Проверь результат: `git branch --show-current` — это `<NN>_<slug>` из `NEXT`, дерево чистое. Не так — останови конвейер.

## Стадия 2 — код

Тот же `subagent`, промпт:

> Ты — стадия `kx_code` автоматического конвейера `/kx_auto`, чистая сессия. Прочитай `.opencode/commands/kx_code.md` и выполни её шаги полностью для текущей ветки. Человека нет: не задавай вопросов; на каждой развилке бери рекомендованный вариант, при его отсутствии — решение в духе ADR и соседнего кода, и запиши его в отчёт. Ищи по codegraph. Прогоняй `make build` и `make test` после каждой законченной части; `make bruno_test` — если менялись REST или UI. Красное не коммить: если после честных попыток тесты не зеленеют, остановись и опиши, что именно красное. Уведомление в ntfy не отправляй. Верни: что сделано по пунктам задачи, коммиты (`git log path..HEAD --oneline`), результаты проверок, что осталось и какие решения приняты.

Проверь: ветка та же, `git log path..HEAD --oneline` содержит коммиты задачи, `git status --short` чистое (незакоммиченное — стоп). Тесты красные — стоп.

## Стадия 3 — ревью, фикс, закрытие

Один `subagent` на все три команды, промпт:

> Ты — стадия `kx_review` → `kx_fix` → `kx_done` автоматического конвейера `/kx_auto`, чистая сессия. Выполни последовательно в этой же сессии, полностью читая и соблюдая файлы `.opencode/commands/kx_review.md`, затем `.opencode/commands/kx_fix.md`, затем `.opencode/commands/kx_done.md`.
>
> - Сначала ревью по `kx_review`. Отчёт оставь в контексте.
> - Находки есть — выполни `kx_fix` по этому отчёту: чини всё, кроме находок, противоречащих ADR/`AGENTS.md` (их оставь и объясни). Затем `kx_done`.
> - Находок нет — так и скажи («ревью без находок»), `kx_fix` пропусти и сразу `kx_done`.
> - `kx_done`: добавь запись в `CHANGELOG.md` и подними версию, как в истории репозитория, если записи о задаче ещё нет; перенеси файл в `todo/done/`; влей ветку в `path` (`--ff-only`, при расхождении `rebase path` и повторные тесты). Ветку не удаляй и не пушь.
> - Человека нет: вопросов не задавай; на развилке бери рекомендованный вариант и записывай решение. Конфликт слияния/ребейза, красные тесты и расхождение спеки с ADR не угадывай — остановись и опиши.
> - Если вложенный `subagent` недоступен, оси `Standards` и `Spec` пройди сам по очереди, по процессу навыка `code-review`: это не повод останавливать конвейер.
> - Проверки `kx_done` (`make build`, `make test`, `make bruno_test`, браузер для UI) выполняй. Если проверку нельзя запустить из-за окружения (нет Docker, Chromium, dev-БД), зафиксируй это в отчёте и продолжай; если она запустилась и красная — стоп, не вливай.
> - Уведомление в ntfy не отправляй — его отправит `kx_auto`.
> - Верни: отчёт ревью по осям, таблицу «находка → что сделано → коммит» (или «находок нет»), что не исправлено и почему, результат `kx_done`, `git log --oneline -3` после вливания и остаток за кадром (push, удаление ветки, релиз).

Проверь: `git branch --show-current` — `path`; файл задачи (и родитель, если был `Closes parent: yes` и все части закрыты) лежит в `todo/done/`; `git log -1` — коммит задачи. Не так — останови конвейер и покажи, на каком шаге застряло.

## Остановка

Конвейер останавливается, когда:

- следующая задача не `ready-for-agent` или заблокирована (естественный конец);
- задача спроектирована в невлитой ветке (`STOP` с подсказкой «спроектирована в ветке») — слияние спек из шага 4 подготовки не удалось само, разбирается человек;
- задача начиналась, но стадия не смогла довести работу: красные тесты, конфликт, грязное дерево, противоречие ADR, ветка уже существует и т. п.

Не начинай следующую задачу, пока текущая не закрыта и не влита в `path`. Не правь код и не коммить сам: это работа подсессий.

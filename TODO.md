### Версионирование json структур

- Возможно потребуется создать отдельный golang модуль.
- Идея в том, чтобы обеспечить обратную совместимость при разработке.
- Для каждого DTO нужно указывать версию.
- Версия состоит из 3х цифр, разделённых точками.
- Последняя цифра увеличивается, если в структуре только добавилось новое поле - это оставляет обратную совместимость.
- Если структура как-то меняется теряя обратную совместимость, то увеличивается средняя цифра и создаётся новая json схема (может и не создаётся, требуется анализ, скорее всего да, потому-что нужно держать несколько json схем, чтобы обеспечивать работу на любой версии протокола).
- Нужно придумать правило для изменения первой цифры (возможно обеспечить версионирование можно и при помощи двух цифр).
- Для каждой отдельной (уникальной или несовместимой) версии нужно держать свою json схему.

### Протокол между клиентом и сервером для передачи состояний

- Нужно организовать протокол между клиентом и сервером для передачи событий, произошедших в предметной области.
- Должно использоваться SSE как основа протокола.
- Для каждого клиента должно быть отдельное соединение.
- В будущем возможно потребуется организовать права доступа для пользователей и событий, но пока это всё единый канал событий.
- В клиенте должна быть возможность просмотра лога событий сервера, для этого нужно сделать строку состояния с отображением текущего времени и кнопкой и надписью Events, которая должна открывать и закрывать лог событий сервера внизу окна под всеми виджетами. В логе должно быть время и описание события. Последние события вверху. Лимит событий должен быть указан константой в коде клиента.
- На сервере источник событий это EventBus.
